# NK1 WorkPass330 — целостность временной памяти

**Дата:** 2026-10-25  
**Рабочая ветка:** `workpass330-temporal-memory-integrity`  
**Область:** `runtime/neuro-kurisu/src/organism/integration/hexis/HexisAdaptationFabric.ts`  
**Статус:** изменения закоммичены; runtime-проверка ещё не выполнена.

## Зачем нужен этот проход

Временная память должна отвечать на вопрос «какое утверждение было актуальным в момент T?», даже когда события приходят не в хронологическом порядке. До исправления новый факт закрывал интервал последнего добавленного факта, хотя более поздний по смыслу факт мог уже существовать. Временная отметка `NaN` также не отсекалась до изменения состояния.

## Что изменено

1. **Проверка до мутации состояния.** Пустой `memoryId`, пустое описание и нечисловое/неограниченное время `validFrom` отклоняются до добавления записи. Пустая строка даты больше не превращается в нулевую отметку времени.
2. **Вставка задним числом и восстановление.** Интервалы строятся по возрастанию `validFrom`, а не по порядку поступления событий. После вставки пересчитываются `validUntil` и `supersedesId`; при восстановлении снимка некорректные временные записи отбрасываются, а допустимая история нормализуется заново.
3. **Детерминированные повторы.** Точная копия утверждения с тем же временем действия, хэшем значения, описанием, уверенностью и источником возвращает исходную запись. Конфликтующее утверждение на той же отметке времени отклоняется, вместо того чтобы создавать неоднозначную историю.
4. **Безопасное чтение.** `temporalAt` возвращает `null` при пустом ID или не конечной отметке времени и не выбирает записи с некорректными временными границами.
5. **Регрессии.** Расширен существующий `tests/integration/hexis-adaptation.mjs`: события добавляются в порядке 3000 → 1000 → 2000; проверяются границы интервалов, линия supersedes, идемпотентный повтор, конфликт одной отметки, пустые/некорректные поля и восстановление старого снимка с повреждённым временем.

## Команды проверки

Из корня полной рабочей копии:

```bash
npm --prefix runtime/neuro-kurisu run test:hexis-adaptation
npm --prefix runtime/neuro-kurisu run typecheck
npm --prefix runtime/neuro-kurisu run test:hexis-server-smoke
```

Эти команды **не запускались** в данном проходе: доступный здесь GitHub-интерфейс позволяет читать и коммитить текстовые файлы, но не выполнять весь проект локально. Новые тесты написаны, но их результат пока не подтверждён выполнением. Combined-status запрос для коммита с тестами вернул пустой список статусов; это не является зелёным CI. Проверку необходимо выполнить на полной checkout-копии.

## Что не выполнено в этом проходе

- Не обновлён большой ZIP в GitHub Releases, и никакой релиз не опубликован.
- Изменения находятся в рабочей ветке, а не в `main` и не в подтверждённом release-артефакте.
- Не подтверждены TypeScript-check, серверный smoke-test и совместимость с реальными миграциями сохранённой истории.
- Не делается заявление о росте общей интеллектуальной эффективности: этот проход исправляет узкую, проверяемую целостность временной памяти.

## Критерий завершения этого участка

Считать участок проверенным можно только после успешного выполнения трёх команд выше на полной checkout-копии, проверки миграции/восстановления состояния с уже сохранёнными временными записями и подтверждения, что CI действительно исполнил тесты. До этого изменения закоммичены, но не production-approved.
