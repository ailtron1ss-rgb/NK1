# Kurisu Neuro Mobile v26 — журнал изменений

## Главное

v26 — это не добавление ещё десятка «мозговых» файлов, а попытка свести существующие слои в один практический контур:

**ввод → восприятие → память → состояние → личность → выбор режима → модель → постобработка → эмоция/аватар → обучение на результате.**

### Исправления

- Удалён Android-конфликт `onnxruntime-node` из npm-зависимостей.
- Исправлены ошибки TypeScript в:
  - `AceMemory`;
  - `MultiLayerConsciousness`;
  - `NeuroEngine`;
  - `ModularBrainPanel`;

- Удалён старый SMS/phone UI.

## Личность

Добавлен `LivingPersona`:

- медленно изменяемые черты;
- ритм диалога;
- предпочитаемая глубина ответа;
- текущая тема;
- знакомство и доверие;
- конфликт;
- количество общих эпизодов;
- привычки разговора;
- долгосрочная инициатива.

Это не заявка на реальное сознание. Это компактная модель поведенческой непрерывности, которую LLM получает вместе с памятью.

## Естественная речь

Убраны искусственные правила:

- «2–5 предложений»;
- обязательная минимальная длина;
- обрезание ответа до 1200 символов;
- автоматическое добавление фраз-заполнителей к коротким ответам.

Теперь короткий ответ допустим, если он естественен, а сложный вопрос может получить длинный ответ.

## Локальная модель

- Node ONNX Runtime больше не используется.
- Локальный inference выполняется через Transformers.js в браузере.
- WebGPU пробуется первым.
- При проблеме WebGPU автоматически выполняется повторная загрузка через WASM.
- Для WASM выставлен консервативный лимит в 2 потока.
- На устройствах с 4+ ГБ `deviceMemory` по умолчанию выбирается SmolLM2 360M Q4; на меньших — SmolLM2 135M.
- Модель загружается лениво.

Актуальные ONNX-варианты SmolLM2 360M действительно доступны для Transformers.js; Q4-вариант сейчас имеет размер около 386 МБ, а q4f16 — около 272 МБ. urlSmolLM2 360M ONNXhttps://huggingface.co/onnx-community/SmolLM2-360M-ONNX

## Облако

- Обновлён основной Gemini-маршрут до `gemini-2.5-flash`.
- Убраны устаревшие Gemini 1.5/2.0 из основного fallback-пула.
- Провайдеры теперь ранжируются автоматически:
  - fast: Groq → Gemini → OpenRouter → Together;
  - strong: Gemini → OpenRouter → Groq → Together.
- При сбое одного провайдера система продолжает следующий.
- Облачный ответ может быть длиннее старого лимита.

Google сейчас помечает Gemini 2.0 как закрытый, а Gemini 2.5 Flash остаётся стабильной моделью; поэтому старый default `gemini-2.0-flash` был неправильным выбором для новой версии. urlGemini API — моделиhttps://ai.google.dev/gemini-api/docs/models

## Ограничения

- Локальная LLM остаётся маленькой моделью и не равна облачной frontier-модели.
- WebGPU зависит от браузера и конкретного GPU.
- Веб-приложение не получает настоящий Android thermal sensor через обычный браузер.
- SQLite FTS5 не внедрён напрямую в браузерный runtime: текущая память остаётся лёгкой localStorage/JSON-архитектурой ради надёжности Termux. Это сознательный компромисс.
- Модель не «становится сознательной» от количества модулей. Архитектура создаёт устойчивое поведение, память, эмоции, инициативу и самооценку.
