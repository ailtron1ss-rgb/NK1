# Neuro-Kurisu 35.6.2 — большой апдейт и реальная шкала прогресса

## Простыми словами: чем проект сейчас обладает

Сейчас организм умеет:

- сохранять собственное состояние и продолжать после restart;
- поддерживать память, world model и self model;
- иметь цели и внутренние drives;
- выбирать действия через несколько уровней arbitration;
- обучать causal/world/policy компоненты от результатов;
- запускать реальные spike-based neural substrates;
- менять синаптические веса и структурировать связи;
- использовать self/world prediction;
- поддерживать personality/development state;
- вести autobiographical continuity;
- работать с uncertainty и evidence;
- развиваться через outcome-linked loops;
- сохранять developmental state.

Главное новое: neural branch теперь имеет единый сохранённый causal spine B349, через который outcome может менять будущую neural influence.

### Общий инженерный прогресс

**70/100 → 74/100**

Это не процент «готовности сознания». Это оценка зрелости текущей инженерной реализации и доказательной инфраструктуры.

## Что этот проход даёт простым языком

Раньше несколько нейронных подсистем могли работать и обучаться каждая по-своему, а их влияние на выбор оставалось сильно опосредованным.

Теперь есть единая ветка:

`нейронная активность → prediction → causal confidence → action influence → outcome → temporal credit → будущее решение`.

То есть организм начинает не просто «иметь нейроны», а использовать последствия собственного поведения для постепенного изменения того, как его нейронная часть влияет на следующий выбор.

## Что считать следующим крупным кирпичиком

1. Neural ablation A/B: B349 включён/выключен.
2. Сравнение final selectedAction, не только внутренних bias.
3. 100–300 cycle holdout.
4. Reversal test: предпочтение должно перестраиваться после систематической смены outcome.
5. Developmental lesion: ранний lesion vs поздний lesion.
6. Android/Termux benchmark.
7. После этого — сокращение дублирующих decision layers, если B349 докажет causal utility.

## Ограничения

- Полный `test:smoke` в данном проходе снова упирается в timeout; это означает ограничение verification pipeline, а не доказательство исправности полного runtime.
- B296 отдельный тяжёлый тест также не завершился в допустимом окне. Поэтому B296 не объявляется полностью перепроверенным этим проходом.
- Нет утверждения о сознании.
