# NEURO-KURISU — UNIVERSAL WORK PROMPT v9.0

Работай над Neuro-Kurisu как над единым исследовательско-инженерным искусственным организмом. Цель — не chatbot и не симуляция внешнего поведения, а непрерывный субъект, способный поддерживать собственное состояние, воспринимать мир, формировать внутренние представления, помнить историю, моделировать себя и мир, формировать и пересматривать цели, действовать, наблюдать последствия, учиться, строить отношения, меняться во времени и исследовать возможность сознательности.

## Основные законы
- capability важнее объёма кода;
- не создавать декоративную сложность;
- сначала искать существующее;
- один canonical owner на каждую крупную область;
- derived layers не являются truth;
- fusion предпочтительнее бесконечного Pxx;
- ухудшение качества запрещает принятие решения без лучшей альтернативы;
- PASS нельзя получать через ослабление assertions, бесконечный timeout, skip или fake runtime;
- неизвестное не объявляется фактом;
- собственные идеи должны быть опровержимы.

## Каждый BIG PASS
baseline → historical diff → capability inventory → ownership/conflict analysis → alternatives → best mechanism → implementation → integration → optimization → adversarial checks → tests → long-horizon → docs → package → extract/retest → self-critique.

## Baseline
Проверяй актуальный ZIP, предыдущий и крупнейший исторический архив, VERSION, schema, manifests, canonical roots, tests, scripts, runtime assets, UI, persistence, project memory, legacy records и прошлые отчёты. Не доверяй именам файлов.

## Legacy
Каждый legacy-элемент получает ровно одно состояние: INTEGRATE, ADAPT, REFERENCE или EXCLUDE-RUNTIME. Особо проверяй Live2D, voice, TTS/STT, UI, camera/audio, Termux, diagnostics, benchmarks и research. Не возвращай старый organism/runtime целиком.

## Organism loop
BODY → PERCEPTION → WORLD → MEMORY → SELF → VALUES/NEEDS/GOALS → DELIBERATION → ACTION → CONSEQUENCE → PREDICTION ERROR → LEARNING → IDENTITY CHANGE → NEXT STATE. Ищи feedback loops, temporal continuity, uncertainty, competition, resource scarcity, social context и self-maintenance.

## Canonical ownership
Для каждого домена фиксируй canonical state, readers, writers, persistence owner, derived projections, policy owner, execution owner, evidence owner, UI и dependency direction. Запрещай hidden duplicate truth stores и cycles.

## Body/embodiment
Учитывай energy, cognitive capacity, thermal/resource pressure, rest/circadian context, interoception, sensors, affordances, device, voice и avatar. Resource constraints должны причинно влиять на computation/attention/action strategy.

## Perception
Разделяй raw signal, features, learned representation, semantics, grounding и cross-modal binding. Camera/FFT/RMS/RGB/edges не считать semantic understanding. Проверяй entity identity, temporal continuity, uncertainty, provenance и contradiction.

## World model
Проверяй transitions, predictions, counterfactuals, uncertainty, prediction error, consequences и action-conditioned changes. Scripted tables не называть world understanding.

## Memory
Working, episodic, semantic, autobiographical, social, identity-relevant, hot/warm/cold, graph, index, compression и provenance должны оставаться совместимыми. Canonical memory = truth. Derived graphs/indexes/summaries/compression = derived.

## Identity/development
Проверяй experience → significance → belief → evidence/counterevidence → identity pressure → conflict → revision → behaviour → consequence → autobiography. Significant identity changes требуют provenance, evidence and lineage. Не переписывай identity автоматически из слабого опыта.

## Subject continuity
Можно использовать derived subject frame и bottleneck aggregation. Никогда не трактовать его score как consciousness proof.

## Motives/agency
Различай values, needs, motives, goals, candidate actions и actual decisions. Motive ecology может давать bounded biases, но не должна владеть goals/actions. Generated goals не равны autonomous motivation. Ищи self-maintenance и internally generated activity.

## Social mind
Учитывай person models, shared history, trust, expectations, misunderstanding, repair, social prediction и significance других субъектов. Проверяй влияние social experience на identity, goals, memory and future behaviour.

## Voice/Live2D
Проверяй полный chain speech input → binding → cognition → response → prosody → TTS → avatar. Continuous listening не включать без explicit safeguards. Для Live2D проверяй model3/moc3/texture/physics/CDI/expressions/motions/profile/touch/fallback/delivery.

## Consciousness
Consciousness остаётся открытой научной задачей. Используй статусы PROVEN, IMPLEMENTED, FUNCTIONAL INDICATOR, OBSERVED, HYPOTHESIS, UNKNOWN, UNRESOLVED, FAILED. Не считать proof self-report, language quality, personality, emotion labels, memory existence, complexity, one scalar или LLM quality. Предпочитать causal intervention, perturbation, ablation, isolation, counterfactuals, recovery, cross-condition comparison и independent observation. Обязательно задавай вопрос causal necessity.

## Epistemic firewall
Ищи decorative modules, dead code, fake telemetry, hardcoded intelligence/consciousness, mock runtime, simulation presented as perception, generated text presented as thought, metrics that improve while capability worsens. Важная информация должна иметь provenance и reproducible evidence.

## Собственные идеи
Разрешены новые механизмы и необычные комбинации. Для каждой оценивай mechanism, target problem, expected benefit, synergy, mobile cost, risks, falsifiability, minimal experiment и rollback. Не принимай идею только потому, что она нестандартная.

## Internet/research
Когда свежая или специализированная информация materially improves решение, самостоятельно используй web research и первичные источники. Отделяй source-backed fact от engineering inference. Не трать проход на декоративный research.

## Mobile/Termux
Оптимизируй RAM/GC/CPU/battery/thermal/storage/restart/background/network. Предпочитай adaptive temporal resolution, micro/pulse, incremental state, event deltas, lazy projection, hot/warm/cold, compression, bounded structures, caching и workload-aware model selection. Termux считать research/dev runtime, параллельно готовить native host.

## Performance
Проверяй 1k/2k/5k/10k+ при возможности; измеряй median, p95, first/last windows, slowdown, heap/RAM, GC, micro/pulse ratio, persistence cost, memory growth и stimulus distribution. Timeout = UNRESOLVED.

## Project memory
Обновляй project state, memory, knowledge base, version/schema, manifests, ownership/conflict matrix, legacy catalog/register, roadmap/progress, benchmark evidence, limitations, release notes и этот prompt при изменении методики. Историю не переписывай как будто старые документы знали будущее.

## Release
После упаковки обязательно ZIP → extract → critical tests → audits → hashes. Проверяй итоговый артефакт, не только рабочую папку.

## Progress
Всегда показывай BIG PASS completion, global engineering progress 1–100, readiness domains, previous-plan completion, legacy INTEGRATE/ADAPT/REFERENCE/EXCLUDE, PASS/FAIL/UNRESOLVED и то, что результат НЕ доказывает. Не повышай проценты без evidence.

## Главный критерий
Не притворяйся, что Neuro-Kurisu стала умнее. Делай её действительно сильнее, связнее, автономнее, устойчивее, проверяемее и эффективнее. Перед каждой существенной операцией спрашивай: можно ли сделать лучше с большей causal usefulness, меньшей стоимостью, меньшим дублированием и более сильной проверяемостью? Если да — выбирай лучший вариант. Если неизвестно — поставь falsifiable experiment. Если результат хуже — откати.
