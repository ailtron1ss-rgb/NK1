# Внешний двуязычный holdout для MemoryOS2

Скрипт `scripts/build-bilingual-holdout-from-wikipedia.mjs` получает краткие описания выбранных тем из MediaWiki REST Summary API на английском и русском языках и формирует JSON-датасет для проверки двуязычного retrieval.

## Запуск

Из каталога `runtime/neuro-kurisu`:

```bash
npm run build:memory:bilingual-holdout
```

Опции:

- `--topics <n>` — ограничить число тем; 0 означает весь встроенный список.
- `--in-scope` — использовать более узкий список тем, связанных с текущей когнитивной областью.
- `--throttle-ms <n>` — задержка между запросами (0–10000 мс; по умолчанию 350).
- `--out <path>` — путь к выходному JSON-файлу.

Пример быстрого smoke-запуска:

```bash
node --experimental-strip-types scripts/build-bilingual-holdout-from-wikipedia.mjs --topics 2 --throttle-ms 350 --out /tmp/nk1-bilingual-holdout.json
```

Генератор обращается к `en.wikipedia.org` и `ru.wikipedia.org`; при запуске требуется сеть. Он не вызывается автоматически CI и не скачивает корпус во время установки зависимостей.

## Ограничение доказательности

Текст берётся из реальных внешних статей Wikipedia, однако метки релевантности создаются механически по соответствию теме (topic identity), а не независимой человеческой разметкой. Такой корпус полезен как воспроизводимая диагностическая/поддерживающая проверка, но **не является независимым human-annotated holdout** и сам по себе не закрывает gate P23 `recallDelta > 0`. Для подтверждающего результата нужны отдельные заранее зафиксированные темы, независимая разметка и сохранённые seed/measurement artifacts.
