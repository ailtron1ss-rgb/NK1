# P26 — True Learning Foundation

## Зачем этот этап

P23 сделал replay и TD-update, но основной `AdaptivePolicyEngine` оставался дискретной таблицей по bucket-контекстам. Это означало, что значительная часть «обучения» могла быть запоминанием конкретных ключей.

P26 вводит отдельную параметрическую функцию ценности, которая обучается по фактическому TD-target и обобщает на непрерывные состояния. Табличный P23 остаётся совместимым слоем, но уже не является единственным механизмом адаптации.

## Что реально обучается

1. `ParametricPolicyLearner` — непрерывное отображение состояния + действия → ожидаемая ценность.
2. `P26TrueLearningEngine` — online TD-learning, replay и измерение holdout generalization.
3. `ContextualWorldModel` — контекстная модель ожидаемого reward и направления следующего состояния.

Обновления параметров сохраняются в state schema и проходят migration 28 → 29.

## Почему это уже обучение, а не просто память

Обученная модель не хранит только точный `contextKey`. На вход подаются нормализованные непрерывные признаки:

- energy;
- cognitive load;
- uncertainty;
- novelty;
- goal pressure;
- social need;
- prediction error;
- attention budget;
- identity coherence;
- body capacity;
- thermal pressure;
- resource risk;
- boredom;
- external input;
- action cost.

Поэтому новое состояние, которого не было в таблице P23, может получать предсказание из выученных параметров.

## Как проверяется честность

Для P26 добавлен отдельный holdout benchmark. Обучающие состояния и проверочные состояния разделяются. Успех считается только по результату на неиспользованных при обучении состояниях.

Встроенный тест P26 показывает:

- до обучения: модель не знает правильное действие;
- после обучения: 1.000 accuracy на отложенной выборке контролируемого окружения;
- число обновлений фиксируется;
- состояние модели можно восстановить после persistence.

Это не является доказательством общего интеллекта. Это доказательство работающего параметрического механизма обучения в узком контролируемом классе задач.

## Чего здесь пока нет

- градиентного обучения большой нейронной сети;
- end-to-end обучения vision/audio;
- обучения на реальном внешнем мире без формализованной reward signal;
- доказанной причинности из одного наблюдательного replay;
- гарантии переноса на задачи, не представленные в feature space.

## Телефонная стратегия

Модель намеренно небольшая:

- фиксированное число признаков;
- семь действий;
- bounded weights;
- без runtime dependencies;
- без GPU requirement;
- online update выполняется за один малый векторный проход.

Это позволяет использовать механизм на среднем Android/Termux устройстве гораздо безопаснее, чем тяжёлую нейронную training stack.

## Режимы

`Phone Eco`: online updates только для важных outcome traces, replay пакетами во время idle/sleep.

`Phone Active`: online update после значимого действия.

`Research`: расширенный replay и holdout experiments.

## Истина о P26

**P26 решает предыдущую проблему «обучение только как bucket table» в техническом смысле.**

Но P26 не решает проблему обучения в общем смысле. Организм всё ещё зависит от заранее выбранного feature space, action space и reward definition. Следующий качественный скачок должен быть в learned perception/representation и в переносе навыков на новые задачи.
