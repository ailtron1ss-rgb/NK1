# P15.5 — Device Hardening и Lifelong Phone Runtime

## Что сделано

P15.5 — первый большой эксплуатационный шаг после P15. Цель — не добавлять ещё один когнитивный модуль, а сделать существующий организм пригоднее для длительной жизни на среднем Android/Termux.

### 1. Реальный autonomous loop

`OrganismRuntime` получил `autoRun`. В server runtime он включён по умолчанию. Цикл выполняется последовательно через существующую очередь runtime, поэтому два когнитивных шага не перекрываются.

При awake-состоянии выполняется `step()`. Во время sleep запускается только редкая consolidation/maintenance операция. Задержка увеличивается автоматически при низком заряде, тепловой нагрузке и высоком давлении RAM.

### 2. Коалесцирование тяжёлых checkpoint

Каждый cognitive cycle по-прежнему меняет состояние в памяти, но disk checkpoint может быть отложен по policy. Есть две границы:

- минимальный интервал между полными checkpoint;
- максимальное число dirty cycles без checkpoint.

Это ограничивает потенциальную потерю состояния после внезапного убийства процесса. В phone profile по умолчанию используется 60 секунд и максимум 2 dirty cycles.

### 3. Реже создаётся `.bak`

Full backup прежнего snapshot теперь не копируется после каждого сохранения. В phone profile backup выполняется раз в 4 успешных saves, при этом первый backup сохраняется сразу.

### 4. Shutdown/sleep flush

Добавлен явный `flush()`. Server shutdown перед освобождением process lock выполняет принудительный checkpoint.

### 5. Persistence telemetry

`FileStateStore` теперь измеряет:

- число save;
- суммарное число записанных байт;
- размер последнего payload;
- длительность последнего save;
- число backup-copy;
- число fsync;
- время последнего save.

Эти данные выдаются через `/api/metrics`.

## Профиль целевого устройства

Целевое устройство пользователя: POCO M7 Pro 5G, 8 GB RAM / 256 GB, Dimensity 7025-Ultra, UFS 2.2. Это не означает, что полный Android soak уже доказан: P15.5 создаёт правильный runtime policy и instrumentation, но 24/72/168-часовые физические прогоны всё равно должны быть проведены на самом телефоне.

## Почему это первый шаг

Сейчас основная угроза не размер TypeScript runtime, а стоимость долговременного I/O и Android background execution. P15.5 сначала делает жизнь организма дешёвой и наблюдаемой. Следующим большим этапом должен быть настоящий Memory/World/Learning upgrade, а не дальнейшее расширение списка subsystem.

## Конфигурация

- `NEURO_PHONE_MODE=true|false`
- `NEURO_INTERVAL_MS=30000`
- `NEURO_CHECKPOINT_MIN_INTERVAL_MS=60000`
- `NEURO_CHECKPOINT_MAX_DIRTY_CYCLES=2`
- `NEURO_BACKUP_EVERY_SAVES=4`

Полный durability режим достигается `NEURO_PHONE_MODE=false` и/или явным обнулением checkpoint interval.
