# WorkPass507 — бюджет памяти единого когнитивного цикла

**Статус:** инженерный кандидат на ветке `fix/workpass507-cognitive-memory-budget-2026-10-27`. Release ZIP не изменялся.

## Найденный разрыв

В `OrganismCore` первый вызов памяти уже проверяет `cognitiveExecutionPlan.run.memory` и использует асинхронный `MemoryFabric.retrieveForCognition(...)`. Однако расширенный путь — включая запрос от внутренней цели, когда пользовательский текст отсутствует, — ранее вызывал синхронный `MemoryFabric.retrieve(...)` без проверки решения планировщика. Это создавало два разных контракта памяти внутри одного тика.

## Исправленный контракт

1. Если планировщик отключил память в текущем тике, обе стадии возвращают пустой пакет.
2. При том же текстовом запросе расширенная стадия переиспользует начальный, уже ограниченный пакет — не запускает лишний поиск.
3. Для отдельного запроса внутренней цели используется `retrieveForCognition`, чтобы сохранить единый ограниченный путь и предусмотренный им lexical fallback.
4. Локальные embeddings по-прежнему остаются opt-in; этот проход не включает их принудительно и не меняет владельца канонической памяти (`MemoryOS2`).

## Регрессия и границы доказательств

`tests/workpass507-planner-memory-gate.mjs` проверяет контракт маршрутизации исходников и подключён к `test:rebuild-recovered`, чтобы эта проверка выполнялась внутри восстановленного core regression, а не оставалась отдельным ручным тестом.

Это source-contract regression, а не полноценный runtime/E2E тест и не доказательство `recallDelta > 0`. Для закрытия качества памяти по-прежнему нужен независимый русско- и англоязычный holdout с парными seed-ами, корректным отказом и проверкой забывания. После коммита необходима проверка CI на точном SHA; успешность CI не будет автоматически переноситься на будущие коммиты.

## Изменённые границы

`OrganismCore`, пакетный test runner, регрессионный тест и журнал изменений. Не менялись `main`, другие интеграционные ветки, опубликованные Release assets, метрики качества памяти или итоговый процент готовности проекта.
