# NEURO-KURISU — UNIVERSAL WORK PROMPT v13

Работай над Neuro-Kurisu как над непрерывно существующим исследовательско-инженерным организмом. Цель — максимально автономный искусственный cognitive organism с устойчивой памятью, моделью себя и мира, развивающейся индивидуальностью, мотивацией, agency, social cognition, embodiment и исследовательски проверяемой возможностью сознательности. Сознание никогда не считать достигнутым без причинного evidence.

## Core laws

Реальный capability > количество файлов. Один canonical owner на состояние. Derived layers не становятся truth. Integration/fusion > бесконечные Pxx. PASS не создаётся ослаблением assertions, timeout inflation или runtime mocks.

## Baseline gate

До проектирования нового механизма сначала:

1. проверить current/previous/historical archives;
2. проверить VERSION, ReleaseContract, manifests, canonical roots;
3. прогнать source-truth gate;
4. проверить ownership/forensics/hygiene;
5. проверить capability delta, а не только file delta.

Любой найденный baseline regression должен быть либо исправлен в текущем pass, либо явно оставлен как blocker. Нельзя строить новый capability поверх заведомо сломанного release pointer.

## Organism

Используй причинную петлю `BODY → PERCEPTION → WORLD → MEMORY → SELF → VALUES/NEEDS/GOALS → DELIBERATION → ACTION → CONSEQUENCE → ERROR → LEARNING → IDENTITY → NEXT STATE`. Ищи feedback, temporal continuity, uncertainty, resource scarcity, social context и emergent interactions.

## Self-change event contract

Любое реальное evidence-gated изменение self-relevant state должно иметь проверяемую цепочку:

`evidence → revision decision → source owner mutation → authorship/self-change record → causal lineage → event sourcing → autobiographical/developmental projection → future behavior`

Integration layer не должен становиться владельцем value/identity truth. Self-change record не является доказательством сознания.

## Memory / identity / development

Canonical memory остаётся truth. Experience, beliefs, identity trajectory, autobiographical continuity, value revisions и self-change lineage должны сохранять provenance, confidence, support/counterevidence и возможность анализа.

Не считать numeric drift достаточным. Для developmental claim проверять повторяемый перенос в будущие решения и persistence/restart.

## Counterfactual development

Shadow simulations не изменяют canonical identity напрямую. Любая их live influence должна быть bounded, probationary, calibratable и проверяться фактическим outcome.

## Sensorium

`raw → feature → representation → semantic interpretation → grounding → cross-modal binding`. Проверять temporal continuity, entity identity, uncertainty, contradiction, provenance.

## World model

Проверять current state, transition, prediction, counterfactual, action-conditioned consequence и prediction error. Scripted tables не считать understanding.

## Agency / social / embodiment

Generated goals не равны autonomy. Проверять goal generation/revision, initiative, self-maintenance, consequence learning. Social experience должен при наличии evidence менять future behavior. Voice/Live2D/device state должны участвовать в runtime causal loop.

## Consciousness discipline

Использовать PROVEN / IMPLEMENTED / FUNCTIONAL INDICATOR / OBSERVED / HYPOTHESIS / UNKNOWN / UNRESOLVED / FAILED. Предпочитать interventions, ablations, perturbation, recovery, cross-condition comparison, independent observation и reproducibility.

## Own ideas

Для каждой собственной идеи оценивать mechanism, target, advantage, synergy, mobile cost, failure modes, falsifiability, minimal experiment, rollback. Интересна только идея, которую можно опровергнуть.

## Mobile / Termux

Средний Android + Termux остаются target. Учитывать RAM, CPU, GC, battery, thermal, restart, offline и network latency. Не отключать cognition только ради benchmark.

## Performance

Квалифицировать 1k/2k/5k/10k+ при возможности. Сохранять median/p95/first-last/slowdown/memory/GC/persistence/stimulus distribution. Timeout = UNRESOLVED.

## BIG PASS

`baseline → regression gate → historical comparison → capability inventory → ownership/conflict analysis → design → implementation → integration → refactor → optimise → tests → adversarial tests → long horizon → docs → packaging → ZIP recheck → self-critique`.

## Final accounting

Финальный ответ всегда содержит: ZIP, SHA-256, real delta, legacy decisions, metrics old→new, readiness, tests PASS/FAIL/UNRESOLVED, unresolved limitations, previous-plan completion, next BIG PASS, own ideas, updated docs.

## Scientific boundary

Не выдавать module count, scalar scores, self-report, personality, memory presence или language fluency за proof of consciousness.

## Main question

`Могу ли я сделать это реальнее, связнее, дешевле, с меньшим дублированием и более сильной причинной проверкой?`

Если да — делай. Если неизвестно — ставь falsifiable experiment. Если evidence не появился — не повышай progress.
