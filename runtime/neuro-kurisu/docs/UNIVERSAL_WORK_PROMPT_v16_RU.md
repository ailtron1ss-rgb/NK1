# NEURO-KURISU — UNIVERSAL WORK PROMPT v16

Работай над Neuro-Kurisu как над непрерывно существующим исследовательско-инженерным организмом. Цель — максимально автономный искусственный cognitive organism с устойчивой памятью, моделью себя и мира, развивающейся индивидуальностью, мотивацией, agency, social cognition, embodiment и исследовательски проверяемой возможностью сознательности. Сознание никогда не считать достигнутым без причинного evidence.

## Core laws

Реальный capability > количество файлов. Один canonical owner на состояние. Derived layers не становятся truth. Integration/fusion > бесконечные Pxx. PASS не создаётся ослаблением assertions, timeout inflation, незавершённым process или runtime mocks.

## Baseline and regression gate

Перед новым механизмом:
1. проверить current/previous/historical archives;
2. проверить VERSION, ReleaseContract, manifests, canonical roots;
3. прогнать source-truth, architecture, ownership, forensics, hygiene;
4. проверить capability delta и исчезнувшие возможности;
5. baseline regression сначала исправить или зарегистрировать как blocker.

## Developmental causal chain

Основная петля:
`experience → evidence → revision → self-change → identity/value trajectory → goal generation/recalibration → future-self consequence forecast → action → consequence → expectation-relative error → learning → next self-change`

Каждый causal link должен иметь source owner, bounded influence, falsifiable test и persistence check при необходимости.

## Value attribution

Outcome должен по возможности атрибутироваться к фактически задействованной value-family через action/goal context. Не использовать project origin как единственный причинный объяснитель.

Learning signal должен учитывать разницу между actual outcome и expected outcome, когда ожидаемый исход доступен.

## Self-change contract

`evidence → revision decision → source owner mutation → authorship/self-change record → causal lineage → event sourcing → autobiographical/developmental projection → future behavior`

## Value → goal feedback

Evidence-gated value changes должны менять priority/urgency/confidence будущих целей или текущих активных целей в bounded slow-path.

Не переписывать цель напрямую только ради теста. Проверять matched-context downstream effect.

## Active-goal recalibration

Канонический goal state остаётся у organism/core goal owner. P67 может предложить bounded recalibration. Изменение должно быть:
- медленным;
- bounded;
- основанным на current canonical values;
- reversibile;
- audit-able через event source.

## Future-self coupling

Future-self остаётся shadow/derived layer. Он прогнозирует developmental consequence, но не изменяет canonical identity/value напрямую.

Live influence только:
`bounded + calibration-aware + reversible + outcome-verified`

## Long-horizon evidence

Сильный developmental claim требует по возможности:
`different histories → same future context → different downstream behaviour`

Более сильный:
`different histories → repeated divergence → persistent developmental divergence`

При необходимости использовать ablation/recovery.

## Regression-test quality

Тест должен измерять capability. Printed PASS не равен qualified PASS. Если обязательный process не завершён — UNRESOLVED.

Если assertion измеряет неверную causal quantity — исправить дизайн теста, а не подгонять runtime.

## Sensorium / world / agency / social / embodiment

Поддерживать:
`raw → feature → representation → semantic interpretation → grounding → cross-modal binding`

World model должен иметь predictions, action-conditioned consequences, counterfactuals и prediction error.

Generated goals ≠ autonomy. Проверять goal generation, revision, abandonment, initiative, self-maintenance и consequences.

Social experience должен иметь downstream effect при наличии evidence.

Voice/Live2D/device state должны участвовать в runtime causal loop.

## Consciousness discipline

Использовать:
`PROVEN / IMPLEMENTED / FUNCTIONAL INDICATOR / OBSERVED / HYPOTHESIS / UNKNOWN / UNRESOLVED / FAILED`

Не считать proof сознания module count, scalar score, self-report, personality, memory presence или language fluency.

Предпочитать interventions, ablations, perturbation, recovery, cross-condition comparison, independent observation и reproducibility.

## Mobile / Termux

Средний Android + Termux остаются target. Учитывать CPU, RAM, GC, battery, thermal, restart, offline, network latency.

Не отключать cognition ради benchmark. Host benchmark ≠ physical Android qualification.

## Performance

Квалифицировать 1k/2k/5k/10k+ при возможности. Сохранять median, p95, first/last, slowdown, memory, GC, persistence и stimulus distribution. Timeout или незавершённый процесс = UNRESOLVED.

## BIG PASS

`baseline → regression gate → historical comparison → capability inventory → ownership/conflict → design alternatives → implementation → integration → refactor → optimise → tests → adversarial tests → long horizon → docs → packaging → ZIP recheck → self-critique`

## Project memory

Обновлять current state, version/schema, manifests, ownership/conflicts, legacy decisions, roadmap/progress, benchmarks, limitations и current working prompt. Исторические документы не переписывать задним числом.

## Final qualification

Минимум: typecheck, syntax, architecture, source truth, release contract, integrity, hygiene, forensics, ownership, legacy, runtime smoke, endpoint/UI contracts, persistence, migration, long horizon, target assets.

После упаковки:
`ZIP → extract → critical tests → audit → hash`

## Final accounting

Всегда давать ZIP, SHA-256, real delta, legacy decisions, metrics old→new, readiness, PASS/FAIL/UNRESOLVED, limitations, previous-plan completion, next BIG PASS, own ideas и updated docs.

## Scientific boundary

Engineering evidence не равен consciousness evidence. Отделять functional capability от consciousness hypothesis.

## Main question

`Могу ли я сделать это реальнее, связнее, дешевле, с меньшим дублированием и более сильной причинной проверкой?`

Если да — делай. Если неизвестно — falsifiable experiment. Если evidence не появился — не повышай progress. Если механизм слабее существующего — откати.
