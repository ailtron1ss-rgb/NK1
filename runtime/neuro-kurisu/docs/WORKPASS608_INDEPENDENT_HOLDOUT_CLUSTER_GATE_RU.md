# WorkPass608 — независимые группы в bilingual memory holdout

**Дата:** 1 ноября 2026 года  
**Ветка:** `workpass70-source`  
**Область:** MemoryOS2 retrieval benchmark / promotion evidence

## Найденный дефект

Парный bootstrap уже пересэмплирует целые `independenceGroupId` кластеры, но языковые ворота допуска ранее проверяли только число строк holdout. Несколько формулировок из одного эпизода могли удовлетворить минимальному числу запросов, хотя статистически независимая выборка оставалась очень маленькой.

## Исправление

- В каждом языковом срезе отдельно подсчитываются уникальные группы для отвечаемых и неотвечаемых holdout-запросов.
- Если `independenceGroupId` отсутствует, используется `example.id` — прежняя семантика независимого примера сохраняется.
- Для каждого языка требуется не меньше независимых отвечаемых групп, чем заданный минимум отвечаемых holdout-запросов, и не меньше независимых неотвечаемых групп, чем заданный минимум no-answer holdout.
- Эти условия включены в языковые gates и итоговый bilingual promotion gate.
- Multi-seed quality signature включает новые cluster counts, чтобы межзапусковая проверка фиксировала не только метрики, но и независимость evidence.

## Регрессии

1. Обычный bilingual fixture с отдельными source groups даёт 8 отвечаемых и 2 неотвечаемые независимые группы на язык.
2. Fixture с тем же количеством строк, но только одной группой на язык, остаётся структурно корректным, однако проваливает независимые evidence gates.
3. Синтетический набор не получает права на продвижение; live memory не меняется.

## Граница утверждений

Изменение укрепляет статистическую честность допуска, но не доказывает улучшение Recall@K. Для такого вывода всё ещё нужен неизменяемый holdout из реальных независимых эпизодов, проверенная разметка, происхождение и лицензия данных, плюс положительный uplift с доверительной поддержкой по RU и EN.
