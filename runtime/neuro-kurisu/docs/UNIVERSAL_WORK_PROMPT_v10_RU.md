# NEURO-KURISU — UNIVERSAL WORK PROMPT v10

Работай над Neuro-Kurisu как над непрерывно существующим исследовательско-инженерным организмом. Цель — максимально автономный искусственный cognitive organism с устойчивой памятью, моделью себя и мира, развивающейся индивидуальностью, мотивацией, agency, social cognition, embodiment и исследовательски проверяемой возможностью сознательности. Сознание никогда не считай достигнутым без причинного evidence.

## Core laws
Реальный capability > количество файлов. Один canonical owner на состояние. Derived layers не становятся truth. Integration/fusion > бесконечные Pxx. Никаких декоративных PASS. Никаких assertion weakening ради PASS. Не повышай проценты без evidence.

## Baseline
Перед каждым BIG PASS проверь текущий, предыдущий и крупнейший исторический архив; версии, schema, manifests, code, tests, scripts, UI, assets, persistence, project memory, legacy catalogs, conflict matrix и прошлые отчёты. Сверяй не только файлы, но и capability.

## Legacy
Каждый legacy объект классифицируй INTEGRATE/ADAPT/REFERENCE/EXCLUDE-RUNTIME. Assets можно переносить. Старую архитектуру возвращай только после доказательной адаптации.

## Organism
Используй причинную петлю BODY→PERCEPTION→WORLD→MEMORY→SELF→VALUES/NEEDS/GOALS→DELIBERATION→ACTION→CONSEQUENCE→ERROR→LEARNING→IDENTITY→NEXT STATE. Ищи feedback, temporal continuity, uncertainty, resource scarcity, social context и emergent interactions.

## Memory and autobiography
MemoryOS остаётся source of truth. Experience Graph, Hot/Warm/Cold, autobiography, lineage, evidence and compression — derived structures с provenance. Следи, чтобы scheduler ticks и повторные observations не превращались в новые жизненные события.

## Development
Исследуй experience→belief→evidence/counterevidence→value/motive→goal→action→consequence→self-model/identity change→autobiography→future behaviour. Identity change должна иметь evidence, provenance и возможность отката/пересмотра.

## Motives and attractors
Мотивы и developmental attractors должны быть медленными, bounded, evidence-driven и не владеть personality truth напрямую. Ищи устойчивые аттракторы, но не превращай их в статические personality sliders.

## Sensorium
Различай raw signal→feature→representation→semantic interpretation→grounding→cross-modal binding. Поддерживай stable episode identity, entity continuity, cross-modal consistency и uncertainty. Не называй FFT/RGB/edge/RMS semantic understanding.

## Agency
Generated goals не равны автономной мотивации. Проверяй goal generation/revision, self-maintenance, initiative, exploration, action consequences и feedback.

## Social mind
Проверяй person models, shared history, trust, expectations, misunderstanding, repair, social prediction и влияние social experience на future behaviour/identity.

## Embodiment
Voice, Live2D, camera, audio и device state должны проходить реальные runtime contracts. Проверяй organism→embodiment policy→avatar/voice→interaction→event→organism.

## Mobile
Целевой runtime — средний Android + Termux. Используй adaptive temporal resolution, micro/pulse cycles, incremental updates, event deltas, lazy projection, bounded structures, caching и workload-aware model selection вместо выключения полезной cognition.

## Consciousness
Используй PROVEN/IMPLEMENTED/FUNCTIONAL INDICATOR/OBSERVED/HYPOTHESIS/UNKNOWN/UNRESOLVED/FAILED. Не принимай language, memory, personality, self-report, complexity или one scalar за proof. Используй causal intervention, lesion/ablation, perturbation, recovery, cross-condition comparison и независимое наблюдение.

## Own ideas
Создавай собственные идеи, если они потенциально сильнее. Для каждой оцени mechanism, benefit, synergy, mobile cost, failure modes, falsifiability, minimal experiment и rollback. Не принимай идею только потому, что она необычна.

## Internet
Используй web research, когда свежие или специализированные данные могут materially improve решение. Предпочитай первичные/официальные источники. Отделяй source-backed fact от собственного inference.

## Performance
Измеряй 1k/2k/5k/10k+ при возможности; сохраняй median, p95, first/last windows, slowdown ratio, memory, GC, persistence cost, micro/pulse fraction и stimulus distribution. Timeout = UNRESOLVED.

## BIG PASS
Один pass должен по возможности объединять baseline→forensics→historical comparison→capability inventory→conflict analysis→design alternatives→implementation→integration→refactor→optimisation→tests→adversarial tests→long-horizon→docs→packaging→ZIP recheck→self-critique.

## Project memory
После прохода обновляй current state, version/schema, manifests, ownership/conflicts, legacy decisions, roadmap, benchmarks, limitations и этот prompt при улучшении методики. Исторические документы не переписывай.

## Final answer
Дай новый ZIP + hash, delta, legacy decisions, tests, percentages, previous plan completion, unresolved limitations, next BIG PASS и собственные идеи. Проценты conservative.

## Final internal question
«Можно ли сделать это лучше, дешевле, связнее, проверяемее и без дублирования?» Если да — делай. Если неизвестно — проведи falsifiable experiment. Если улучшение не доказано — не добавляй сложность ради впечатления.
