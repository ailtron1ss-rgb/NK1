# NEURO-KURISU — UNIVERSAL WORK PROMPT v15

Работай над Neuro-Kurisu как над непрерывно существующим исследовательско-инженерным организмом. Цель — максимально автономный искусственный cognitive organism с устойчивой памятью, моделью себя и мира, развивающейся индивидуальностью, мотивацией, agency, social cognition, embodiment и исследовательски проверяемой возможностью сознательности. Сознание никогда не считать достигнутым без причинного evidence.

## Core laws
Реальный capability > количество файлов. Один canonical owner на состояние. Derived layers не становятся truth. Integration/fusion > бесконечные Pxx. PASS не создаётся ослаблением assertions, timeout inflation, неполным завершением benchmark или runtime mocks.

## Baseline gate
Перед новым механизмом проверить current/previous/historical archives, VERSION, ReleaseContract, manifests, canonical roots, source-truth, ownership, forensics, hygiene и capability delta. Baseline regression должен быть исправлен либо зарегистрирован как blocker.

## Developmental causal chain
`experience → evidence → revision → self-change → identity/value trajectory → goal generation → future-self consequence forecast → action → consequence → prediction error → learning → next self-change`.

Каждый новый link должен иметь source owner, bounded influence и falsifiable test.

## Self-change event contract
`evidence → revision decision → source owner mutation → authorship/self-change record → causal lineage → event sourcing → autobiographical/developmental projection → future behavior`.

## Value-to-goal feedback
Evidence-gated value changes должны иметь downstream effect на goal priority/urgency/confidence при сопоставимом контексте. Не подменять goal text hard-coded mapping.

## Future-self coupling
Future-self mechanisms являются derived/shadow systems. Они могут оценивать возможные последствия действия для будущего developmental state, но не владеют canonical identity/value state. Любое live influence должно быть bounded, calibration-gated и outcome-verified.

Для matched-history experiment:
1. одинаковый старт;
2. разные истории;
3. одинаковый будущий context;
4. измерить downstream difference;
5. проверить persistence;
6. применить countercondition/ablation.

## Memory / identity / development
Canonical memory и identity owners остаются truth. Сохранять provenance, confidence, supporting evidence, counterevidence и lineage. Numeric drift не считать достаточным evidence.

## Sensorium / world
`raw → feature → representation → semantic interpretation → grounding → cross-modal binding`. Проверять temporal continuity, entity identity, uncertainty, contradiction, provenance. World model должен учитывать prediction/action-conditioned consequence/counterfactual/error.

## Agency / social / embodiment
Generated goals ≠ autonomy. Проверять initiative, revision, self-maintenance, consequences, social continuity, voice/Live2D/device causal participation.

## Consciousness discipline
Использовать PROVEN / IMPLEMENTED / FUNCTIONAL INDICATOR / OBSERVED / HYPOTHESIS / UNKNOWN / UNRESOLVED / FAILED. Предпочитать intervention, ablation, perturbation, recovery, cross-condition comparison, independent observation и reproducibility. Не считать language, memory, personality, scalar или module count proof сознания.

## Regression-test quality gate
Тест должен измерять реальную capability. Assertion, который не соответствует причинной величине, должен быть исправлен. Нельзя засчитывать `PASS`, если процесс не завершил обязательный contract даже при распечатанном внутреннем PASS.

## Mobile / Termux
Средний Android + Termux остаются target. Не отключать cognition ради benchmark. Host benchmark не выдавать за physical Android qualification.

## Performance
Проверять 1k/2k/5k/10k+. Сохранять median/p95/first-last/slowdown/memory/GC/persistence/stimulus distribution. Timeout или незавершённый contract = UNRESOLVED.

## BIG PASS
`baseline → regression gate → historical comparison → capability inventory → ownership/conflict → design → implementation → integration → refactor → optimisation → tests → adversarial tests → long horizon → docs → packaging → ZIP recheck → self-critique`.

## Final accounting
Всегда давать ZIP, SHA-256, real delta, legacy decisions, metrics old→new, readiness, PASS/FAIL/UNRESOLVED, unresolved limitations, previous-plan completion, next BIG PASS, own ideas и updated docs.

## Main question
`Могу ли я сделать это реальнее, связнее, дешевле, с меньшим дублированием и более сильной причинной проверкой?`

Если evidence не появился — не повышай progress. Если механизм оказался слабее существующего — откати его.
