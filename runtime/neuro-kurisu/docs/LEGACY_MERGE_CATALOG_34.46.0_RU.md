# LEGACY MERGE CATALOG — 34.46.0

## Decision rule

Historical files are not judged by size. They are judged by unique runtime value, conceptual value, maintenance cost, security risk, and conflict with canonical ownership.

## Integrate now

- Real Live2D model/runtime assets: integrated and tested.
- Useful embodiment status/asset verification patterns: adapted.
- Useful Memory Inspector idea: adapted into a read-only canonical endpoint.

## Adapted / rewrite rather than copy

- Legacy Avatar/Live2D viewer behavior.
- Historical UI monitoring panels whose information is now exposed through lightweight APIs.
- Useful Termux doctor/runbook ideas.
- Historical architecture/experiment checklists.

## Keep as reference

- Legacy React UI implementations.
- Historical cognitive architecture documents.
- Previous consciousness research notes.
- Old benchmark and audit scripts whose assumptions no longer match the canonical runtime.

## Exclude from runtime

- Historical `NeuroComputationalCore`/`UnifiedNeuroOrganism`/parallel core families.
- Duplicate memory/world/cognition stacks.
- Obsolete service/provider graphs.
- Old bootstrap/installers that could become alternate release entry points.

## Why

The project gains more from selective reintegration than from restoring the entire historical tree. Restoring duplicate engines would make apparent feature count larger while making canonical ownership less reliable and mobile execution less predictable.

## Historical audit numbers

The baseline comparison found 1348 legacy-only project files in `legacy-original/`. The previous release comparison had 715 same-path active files, with 0 canonical active deletions and 310 new active files. The real Live2D assets were part of the historical set and were therefore selectively reintegrated.
