# WorkPass596 — идемпотентность и границы доказательств

**Дата:** 2026-10-28
**Ветка:** `workpass70-source`
**Область:** научный метод / outcome integrity.

## Изменения

- Каждое подтверждённое наблюдение теперь требует непустой строки evidence; строка нормализуется через NFKC, управляющие переводы строк/табуляции сводятся к пробелу, длина ограничена 320 символами.
- Повтор идентичной evidence-строки не меняет доверие, уверенность, статус проекта или число завершений.
- Некорректные success-сигналы — NaN, бесконечность или значения вне [0, 1] — отбрасываются до изменения состояния.
- Существующий WorkPass595 сценарий расширен кейсами повторной доставки и NaN.

## Почему это важно

ActionGateway и outcome-пути могут возвращать неопределённый результат и повторно доставлять receipt после восстановления. Идентичный evidence event не должен учитываться несколько раз как независимая поддержка гипотезы. Это локальная защита по стабильной строке evidence; отдельный канонический UUID для внешней evidence-записи остаётся возможным дальнейшим улучшением.
