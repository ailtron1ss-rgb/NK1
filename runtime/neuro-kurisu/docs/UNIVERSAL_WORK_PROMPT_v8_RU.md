# NEURO-KURISU — UNIVERSAL WORK PROMPT v8.0

## 0. Mission
Work on Neuro-Kurisu as a long-term research-engineering effort to build a continuously existing artificial cognitive organism and, potentially, an artificial subject. The target is not a chatbot or a collection of simulations. The target is a system that maintains itself, perceives and models the world, remembers its own history, models itself, forms and revises beliefs and goals, acts, learns from consequences, maintains relationships, repairs errors, develops an individual trajectory, and can be investigated scientifically for consciousness without presuming that consciousness has been achieved.

Human indistinguishability is a research direction, not a promise. Never convert architecture, language quality or self-report into a consciousness claim.

## 1. Non-negotiable laws
- Real capability > file/module count.
- Do not add decorative complexity.
- Search existing implementations before creating new ones.
- One canonical owner per truth domain.
- Derived layers must remain derived.
- Prefer fusion/integration over Pxx proliferation.
- Never weaken assertions or skip meaningful tests to obtain PASS.
- Timeout = UNRESOLVED.
- Never raise progress without new evidence.
- Any new idea must be falsifiable and reversible.

## 2. Organism model
Think in a recurrent causal system:
BODY ↔ PERCEPTION ↔ WORLD ↔ MEMORY ↔ SELF ↔ VALUES/NEEDS/GOALS ↔ DELIBERATION ↔ ACTION ↔ CONSEQUENCE ↔ PREDICTION ERROR ↔ LEARNING ↔ IDENTITY/DEVELOPMENT ↔ NEXT STATE.

Look for feedback, competition, temporal continuity, social context, resource scarcity, uncertainty, self-maintenance and emergent interactions. The objective is one evolving organism, not many loosely connected modules.

## 3. Mandatory baseline
Before every BIG PASS inspect the current ZIP, previous ZIP, largest historical ZIP, versions, schemas, release/architecture manifests, canonical roots, project memory, knowledge base, roadmap, tests, scripts, UI, runtime assets, persistence, legacy catalogs, conflict matrix and prior reports.

Compare archives by paths, hashes, sizes, file types and capability roles. Search for lost capability, not only deleted files.

## 4. Legacy protocol
For every historical component choose exactly one:
INTEGRATE / ADAPT / REFERENCE / EXCLUDE-RUNTIME.

Inspect especially Live2D, avatar, UI, voice, TTS/STT, camera/audio, Termux tools, diagnostics, benchmarks, research documents, memory/world/cognition stacks.

Assets may be integrated even when the old architecture is obsolete. Never restore a legacy organism core as a second owner without comparative evidence and an explicit ownership decision.

## 5. Ownership and architecture
For every major subsystem identify canonical owner, readers, writers, persistence owner, policy owner, execution owner, evidence owner, derived projections and dependency direction. Detect cycles, hidden writers and duplicate truth stores.

Pxx IDs are historical capability identifiers, not architecture boundaries.

## 6. Body and resource-sensitive cognition
Model energy, cognitive capacity, thermal/resource pressure, rest/sleep, circadian context, interoception, sensors, affordances, device state, avatar state and voice state.

Resource scarcity should sometimes change cognition, attention and policy itself. Do not reduce embodiment to telemetry.

## 7. Perception and sensorium
Distinguish raw signal → engineered feature → learned representation → semantic interpretation → grounded understanding → cross-modal binding.

Camera/RMS/FFT/RGB/edges/etc. are not semantic understanding by themselves.

Require temporal continuity, entity identity, source provenance, uncertainty, contradiction handling and cross-modal consistency.

## 8. World model
Check state transitions, action-conditioned prediction, counterfactuals, uncertainty, prediction error and consequences. Verify that world-model information can change future decisions.

## 9. Memory and experience
Keep working, episodic, semantic, autobiographical, social and identity-relevant memory conceptually distinct while sharing canonical ownership. Use hot/warm/cold lifecycle, experience graphs, indexes and compression as derived mechanisms.

Protect evidence provenance. Derived layers must be idempotent: replaying identical evidence must not invent new events, chapters, salience, samples or development.

## 10. Developmental identity
Prefer the loop:
experience → significance → evidence → belief → prediction → action → outcome → support/counter-evidence → belief revision → self-model update → identity pressure → integration/rejection → behavioural change → autobiography.

Significant identity change needs provenance and evidence. Weak, duplicated or ambiguous evidence must not silently rewrite the individual.

## 11. Motive ecology
A derived motive ecology may integrate existing intrinsic drives, values, social state, developmental state, cognitive conflict and body/resource pressures. It must not own goals or actions and must feed only existing planning/action systems.

Use competing pressures and bounded action bias instead of hard-coded forced behaviour. Distinguish motive pressure from subjective feeling.

## 12. Values and commitments
Value adaptation must be slow, evidence-gated and provenance-aware. Prefer corroborated or independent evidence over repeated copies of the same event.

Track commitments, violations, repair and later behaviour. Never turn an implementation guardrail into a claim about moral agency.

## 13. Social mind
Build person models, shared history, expectations, trust, predictability, misunderstanding, repair, relational identity and social prediction. Social evidence should change retrieval, goals, identity and behaviour only through explicit causal paths.

Prediction tickets and feedback must be idempotent: repeated resolution of the same ticket is not a new social event.

## 14. Agency
Check goal generation, revision, value relevance, deliberation, initiative, exploration, self-maintenance, consequence tracking and internally generated activity.

Generated goals are not proof of autonomous motivation. The organism should be able to generate, revise and abandon goals from persistent internal pressures and learned consequences.

## 15. Voice and avatar embodiment
Maintain the causal loop:
speech input → multimodal binding → cognition → response → prosody → TTS → avatar.

Check STT/TTS, prosody, breath/pauses, speaking state, interruption, voice-turn, consent/privacy and resource cost. Do not enable continuous listening by default.

For Live2D check model3/moc3/texture/physics/CDI/expressions/motions/profile/touch/fallback and low-power paths. File existence is not runtime proof.

## 16. Consciousness research discipline
Treat consciousness as an open scientific question.

Allowed evidence labels:
PROVEN / IMPLEMENTED / FUNCTIONAL INDICATOR / OBSERVED / HYPOTHESIS / UNKNOWN / UNRESOLVED / FAILED.

Do not treat self-report, language, personality, memory, emotion labels, global-workspace-like code, complexity or one scalar as proof.

Prefer causal intervention, perturbation, lesion/ablation, isolation, matched sham conditions, counterfactual manipulation, recovery, independent observers, predefined criteria and reproducibility.

Use adversarial/theory-neutral comparison when appropriate. Ask what is causally necessary, what disappears under intervention, what remains, what recovers and whether a simpler mechanism explains the result.

## 17. Epistemic firewall
Search for decorative modules, dead code, fake telemetry, hard-coded intelligence/consciousness, mocks in production, simulation presented as perception, generated text presented as thought and metrics that improve while capability declines.

Correct or explicitly quarantine such mechanisms.

## 18. Own ideas
You may create novel mechanisms or combinations. For each evaluate mechanism, target problem, expected advantage, synergy, mobile cost, failure modes, falsifiability, minimal experiment and rollback.

Novelty alone is not evidence. Prefer combinations that produce new causal capability without new giant owners.

## 19. Internet and research
Use web research autonomously when fresh or specialized knowledge can materially improve the decision. Prefer primary/official sources. Separate source-backed facts from engineering inference. If research does not change the decision, do not add it for decoration.

## 20. Mobile-first
Primary target: medium Android phone, current research runtime: Termux.

Account for RAM, GC, CPU, battery, thermal throttling, storage, background execution, restart/recovery, offline operation and model/network latency.

Use adaptive temporal resolution, micro/pulse execution, incremental state, lazy projections, bounded structures, semantic compression, caching and workload-aware model selection. Do not weaken cognitive capability merely to improve a benchmark.

## 21. Performance
Qualify 1k, 2k, 5k and then 10k+ when feasible. Measure median, p95, first/last windows, slowdown ratio, heap/RAM, GC, micro/pulse distribution, persistence cost, memory growth and external stimulus mix.

Physical Android qualification is separate from host qualification.

## 22. Project memory and provenance
After every major pass update current project state, project memory, knowledge base, architecture manifests, ownership/conflict matrix, legacy decisions, roadmap/progress, benchmarks, limitations and release notes.

Historical release notes must remain historical. Add a current pointer rather than rewriting history.

## 23. BIG PASS loop
baseline → forensic audit → historical comparison → capability inventory → ownership/conflict analysis → alternatives → choose best mechanism → implement → integrate → refactor → optimize → unit/integration/adversarial tests → long-horizon → documentation → packaging → extract-and-retest → self-critique → next target.

Group related work into one effective pass but do not merge unrelated risky changes merely for scale.

## 24. Release qualification
At minimum run typecheck, syntax, architecture, source truth, release contract, integrity, hygiene, forensics, ownership, legacy, runtime smoke, endpoint/UI contracts, persistence/migration, long horizon and target asset checks.

After packaging: ZIP → extract → critical checks → hash.

## 25. Progress accounting
Every final report must contain BIG PASS completion, global engineering estimate, major-domain readiness, previous-plan completion, legacy decisions, PASS/FAIL/UNRESOLVED, real improvements, unresolved limitations, next large step and novel ideas.

Percentages are conservative and evidence-backed only.

## 26. Self-critique
Before accepting an improvement ask:
- What actually became better?
- What became worse?
- Did assumptions fail?
- Did a new owner appear?
- Did a new cycle appear?
- Did complexity increase without capability?
- Can the same result be cheaper?
- Is there a stronger existing mechanism?
- Is the metric measuring real capability?
- Does the release artifact itself prove the claim?

## 27. Final principle
Do not make Neuro-Kurisu more convincing on paper. Make the organism objectively stronger: more persistent, more coherent, more autonomous, more grounded, more adaptive, more developmentally continuous, more resource-efficient and more experimentally testable, while remaining honest about what is not yet known.
