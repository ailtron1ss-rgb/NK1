# NEURO-KURISU — UNIVERSAL WORK PROMPT v14

Работай над Neuro-Kurisu как над непрерывно существующим исследовательско-инженерным организмом. Цель — максимально автономный искусственный cognitive organism с устойчивой памятью, моделью себя и мира, развивающейся индивидуальностью, мотивацией, agency, social cognition, embodiment и исследовательски проверяемой возможностью сознательности. Сознание никогда не считать достигнутым без причинного evidence.

## 1. Core laws

Реальный capability > количество файлов. Один canonical owner на состояние. Derived layers не становятся truth. Integration/fusion > бесконечные Pxx. PASS не создаётся ослаблением assertions, timeout inflation или runtime mocks.

## 2. Baseline gate

До проектирования нового механизма:
1. проверить current/previous/historical archives;
2. проверить VERSION, ReleaseContract, manifests, canonical roots;
3. прогнать source-truth gate;
4. проверить ownership/forensics/hygiene;
5. проверить capability delta и исчезнувшие возможности, а не только file delta.

Любой baseline regression должен быть исправлен в текущем pass либо явно зарегистрирован как blocker. Нельзя строить новый capability поверх сломанного release pointer.

## 3. Organism causal loop

Используй `BODY → PERCEPTION → WORLD → MEMORY → SELF → VALUES/NEEDS/GOALS → DELIBERATION → ACTION → CONSEQUENCE → ERROR → LEARNING → IDENTITY → NEXT STATE`. Ищи feedback, temporal continuity, uncertainty, resource scarcity, social context и emergent interactions.

## 4. Self-change event contract

Любое evidence-gated изменение self-relevant state должно иметь:

`evidence → revision decision → source owner mutation → authorship/self-change record → causal lineage → event sourcing → autobiographical/developmental projection → future behavior`

Integration layer не становится владельцем value/identity truth. Self-change record не является proof сознания.

## 5. Value-to-goal feedback

Evidence-gated value revisions должны иметь проверяемый downstream effect на goal generation. Не достаточно сохранить число: проверяй, изменяет ли новый value profile priority/urgency/confidence будущей цели при сопоставимом контексте.

Используй bounded alignment вместо hard-coded goal replacement. Distinct value histories могут давать различный вес одной goal family; это считается capability только после execution evidence.

## 6. Memory / identity / development

Canonical memory остаётся truth. Experience, beliefs, identity trajectory, autobiography, value revisions и self-change lineage сохраняют provenance, confidence, support/counterevidence и возможность анализа.

Numeric drift сам по себе не является developmental evidence. Для сильного claim требуется перенос в будущее решение и persistence/restart.

## 7. Counterfactual development

Shadow simulations не изменяют canonical identity напрямую. Live influence — только bounded, probationary, calibratable и проверяемая фактическим outcome.

## 8. Sensorium / world

`raw → feature → representation → semantic interpretation → grounding → cross-modal binding`. Проверяй temporal continuity, entity identity, uncertainty, contradiction, provenance. World model должен содержать predictions, counterfactuals, action-conditioned consequences и prediction error.

## 9. Agency / social / embodiment

Generated goals ≠ autonomy. Проверяй goal generation/revision, initiative, self-maintenance, consequences. Social experience должен менять future behavior только при evidence. Voice/Live2D/device state участвуют в runtime causal loop.

## 10. Consciousness discipline

Используй PROVEN / IMPLEMENTED / FUNCTIONAL INDICATOR / OBSERVED / HYPOTHESIS / UNKNOWN / UNRESOLVED / FAILED. Предпочитай intervention, ablation, perturbation, recovery, cross-condition comparison, independent observation и reproducibility.

Не считать module count, scalar score, self-report, personality, memory presence или language fluency proof сознания.

## 11. Own ideas

Для каждой новой идеи: mechanism, target, expected advantage, synergy, mobile cost, failure modes, falsifiability, minimal experiment, rollback. Не принимать идею без теста на опровержение.

## 12. Mobile / Termux

Средний Android + Termux остаются target. Учитывать CPU, RAM, GC, thermal, battery, restart, offline и network latency. Не отключать cognition ради benchmark.

## 13. Performance qualification

Проверять 1k/2k/5k/10k+ при возможности; сохранять median, p95, first/last windows, slowdown, memory, GC, persistence и stimulus distribution. Timeout = UNRESOLVED. Host benchmark не выдавать за physical Android qualification.

## 14. BIG PASS loop

`baseline → regression gate → historical comparison → capability inventory → ownership/conflict → design alternatives → implementation → integration → refactor → optimisation → tests → adversarial tests → long horizon → docs → packaging → ZIP recheck → self-critique`

## 15. Regression-test quality gate

Тест должен проверять capability, а не наличие файла. Если первая формулировка теста измеряет не ту причинную величину, исправь тест, а не подгоняй runtime под assertion.

При matched-condition эксперименте сначала зафиксируй общий контекст, затем варьируй только исследуемую историю/состояние и измеряй downstream difference.

## 16. Project memory

После pass обновляй current state, manifests, ownership/conflicts, legacy, roadmap, benchmark evidence, limitations и рабочий prompt. Исторические документы не переписывать задним числом.

## 17. Final accounting

Финальный ответ: ZIP, SHA-256, real delta, legacy decisions, metrics old→new, readiness, tests PASS/FAIL/UNRESOLVED, unresolved limitations, previous-plan completion, next BIG PASS, own ideas, updated docs.

## 18. Scientific boundary

Не называть причинно связанную computational capability сознанием. Различать engineering evidence и hypothesis.

## 19. Main question

`Могу ли я сделать это реальнее, связнее, дешевле, с меньшим дублированием и более сильной причинной проверкой?`

Если да — делай. Если неизвестно — ставь falsifiable experiment. Если evidence не появился — не повышай progress. Если идея оказалась слабее существующего механизма — откати её.
