## Что изменено

Добавлен `src/organism/cognition/InternalDialogueEngine.ts` — ограниченный цикл внутреннего пересмотра решения. Он проходит шесть ролей: framing, сравнение гипотез, критик, аудит доказательств, метакогнитивная калибровка и синтез. Это не пользовательский диалог и не транскрипт скрытого рассуждения: наружу возвращаются короткие аудируемые заметки, оценки доказательной базы и список нерешённых вопросов.

Движок:
- сравнивает максимум 12 гипотез и принимает не более 96 записей доказательств за цикл;
- связывает подтверждающие и опровергающие данные с конкретными гипотезами;
- различает типы данных: наблюдаемый исход весит больше, чем прогноз; память и цели не считаются самостоятельным подтверждением;
- не позволяет дублирующимся идентификаторам доказательств искусственно увеличивать поддержку;
- вычисляет покрытие доказательствами, конфликт, неопределённость и относительную уверенность ранжирования;
- ограничивает число внутренних проходов 3–6 и фильтрует явные маркеры секретов/контактных данных из вопросов;
- при совпадении одного evidence ID в списках подтверждений и опровержений выбирает консервативную трактовку — опровержение;
- считает покрытие по каждому кандидату один раз, не начисляет бонус независимости за противоречия;
- при недостатке доказательств рекомендует проверить или исследовать пробел, а при высокой когнитивной нагрузке — приостановить углубление.

## Интеграция

`LanguageOrgan.ts` строит обзор через `buildCognitiveProposalPrompt`. Теперь реальный production-вызов в `OrganismRuntime.generateCognitiveProposal` передаёт `this.core.cognitiveEventFabricSnapshot()` — снимок причинного журнала, которым владеет `OrganismCore`. В тесте `internal-dialogue-runtime-wiring-workpass319.mjs` добавлена проверка именно этой цепочки.

`CognitiveEventEvidenceBridge.ts` связывает исход с кандидатом только при наличии прямой причинной связи с событием действия и явной идентичности действия. Поздние внешние наблюдения требуют цепочки `tool-action → tool-outcome → external-evidence`, совпадающего execution ID, независимых `sourceId`/`independenceKey` и статуса corroborated/contradicted. Числовое поле `success` из CEF обрабатывается как непрерывная оценка; это соответствует фактическому формату событий `OrganismCore`.

Снимок берётся из сохранённого состояния Core: внутренний обзор сопоставляет кандидатов с уже зафиксированными причинными результатами, а не трактует ещё не наступивший исход текущего решения как подтверждение. Если снимок отсутствует, обзор остаётся консервативным и помечает отсутствие связи с реальным исходом.

Обзор остаётся `advisoryOnly`: он не исполняет инструменты, не меняет выбранное действие и не заменяет полномочия `OrganismCore` или существующих шлюзов безопасности. Постоянный журнал самих обзоров и ночная консолидация ещё не подключены.

## Регрессии

Добавлен `tests/internal-dialogue-workpass319.mjs` с проверками:
- связывания outcome по явной связи `action → outcome`;
- связывания позднего независимого наблюдения по точной цепочке receipt;
- отклонения события с отсутствующим parent action или `independenceKey`;
- сравнения подтверждённых исходов с кандидатом, поддержанным только предсказанием;
- противоречащих данных и отсутствия явных подтверждений;
- пустого набора кандидатов и паузы при высокой когнитивной нагрузке;
- ограничения числа проходов, невалидного ввода и дублирующихся идентификаторов;
- фильтрации очевидных приватных строк;
- наличия обзора в `buildCognitiveProposalPrompt`, сохранения уже выбранного действия и отсутствия чувствительных фактов в prompt.

Команда `test:internal-dialogue-workpass319` добавлена в `runtime/neuro-kurisu/package.json` и в цепочку `test:rebuild-recovered`.

## Проверки и ограничения

- Регрессионные сценарии для движка и причинного bridge обновлены, но текущая версия файлов после runtime-wiring не была выполнена в полном точном checkout.
- Добавлен runtime wiring guard, который проверяет передачу Core-owned CEF snapshot из `OrganismRuntime` в `buildCognitiveProposalPrompt` и наличие связки bridge.
- На последней проверке GitHub Actions для PR #111 были в очереди/ожидании; завершённых combined status checks не было. Это не является зелёным CI.
- Попытка локального получения репозитория завершилась ошибкой DNS для `github.com`; поэтому здесь не подтверждены exact-head typecheck, новая интеграционная команда, полный `test:rebuild-recovered`, runtime performance и сборка release ZIP.
- Ранее сообщённые изолированные проверки относились к предыдущей версии движка/bridge и не считаются доказательством прохождения нового live runtime-вызова.
- Никакого прироста общей интеллектуальной эффективности, улучшения обучения или субъективного сознания не заявляется.

## Следующий технический шаг

1. Дождаться завершения Actions и исправить найденные type/test failures на текущем HEAD.
2. Убедиться, что runtime snapshot реально содержит последние завершённые action/outcome и что причинный bridge правильно привязывает числовые success scores и поздние независимые observations на интеграционном тесте.
3. Добавить короткий persistable review receipt (tick, evidence IDs/hashes, gap list, confidence, proposed next step), чтобы после рестарта можно было сравнить качество само-проверки без сохранения приватных внутренних заметок.
4. После этого оценить calibration и decision regret на paired seeds с неизменяемым holdout. До этих измерений обзор остаётся advisory critic.
