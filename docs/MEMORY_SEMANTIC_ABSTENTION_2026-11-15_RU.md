# Предохранитель семантического извлечения — 15.11.2026

## Проблема

Локальный embedding-поиск в `MemoryOS2.previewRetrieveWithEmbeddings()` ранжировал все доступные векторы и мог заменить grounded lexical fallback даже тогда, когда максимальная cosine similarity была близка к нулю. Валидный вектор сам по себе не доказывает, что воспоминание отвечает на вопрос.

Это особенно опасно для явно неразрешимых запросов: обычный lexical retrieval уже умеет воздерживаться, а embedding-ветка могла вернуть случайный верхний элемент.

## Изменение

- Семантический результат может заменить lexical fallback только если хотя бы один кандидат достигает минимальной cosine similarity.
- Начальное консервативное значение — `0.72`; среда `NK_EMBEDDINGS_MIN_SIMILARITY01` может задавать значение в ограниченном диапазоне `0.60–0.95`.
- Если ни один кандидат не прошёл порог, возвращается исходный lexical fallback без изменения канонической памяти.
- В диагностике указываются минимальный порог, лучшая наблюдавшаяся similarity и причина воздержания.
- Ошибка провайдера, timeout или холодный индекс по-прежнему оставляют lexical fallback доступным.

## Границы доказательств

Порог `0.72` — защитная стартовая настройка, а не откалиброванная гарантия качества. Он не является доказательством recall uplift и может снизить recall некоторых валидных перефразировок. Его нельзя снижать и нельзя включать embedding-поиск по умолчанию на основании синтетического fixture.

Перед изменением порога требуется offline-сравнение на замороженном, независимо размеченном RU/EN корпусе с answerable и unanswerable holdout-группами, paired confidence intervals, MRR non-inferiority и проверкой частоты неподдержанных ответов.

Runtime semantic retrieval остаётся opt-in через `NK_EMBEDDINGS_RUNTIME_ENABLED`. Никакие live memory rows, identity, policy, approvals или release state этим предохранителем не изменяются.
