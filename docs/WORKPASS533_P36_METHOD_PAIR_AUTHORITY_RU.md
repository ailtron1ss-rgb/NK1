# WorkPass533 — фиксированная пара методов для P36 signed-ledger evaluator

**Дата:** 25 октября 2026 г.  
**Ветка:** `feature/learning`  
**PR:** [#79 → integration](https://github.com/ailtron1ss-rgb/NK1/pull/79)  
**Проверка:** код и регрессионный сценарий обновлены; точный HEAD не подтверждён запуском typecheck/CI.

## Почему это важно

Подписанный реестр защищает факты исхода, но сам по себе не предотвращает выбор наиболее выгодного сравнения после просмотра результатов. Если вызывающая сторона свободно выбирает `baselineMethod` и `treatmentMethod`, она может перебрать несколько вариантов и передать в P36 только удачную пару. Тогда подписи аутентифицируют отдельные исходы, но не защищают статистический выбор.

## Что изменено

`P36VerifiedOutcomeLedgerEvaluatorConfig` теперь требует зафиксировать в доверенной host-конфигурации:
- `baselineMethod`;
- `treatmentMethod`;
- `taskFamily`.

Идентификаторы проходят ограниченную нормализацию; baseline и treatment обязаны различаться. Каждый runtime-запрос сверяется с этой хостовой конфигурацией. Запрос с другим кандидатом или семейством отклоняется до чтения/агрегации результатов. Поэтому адаптер создаётся под одно заранее определённое сравнение, а не является произвольным API для поиска выгодной пары.

Существующие границы сохранены:
- реестр должен соответствовать точному task manifest;
- учитываются только подписанные и повторно аутентифицированные independent-verifier исходы из holdout split;
- все задачные ячейки должны быть парно покрыты baseline и treatment на каждом seed; требуется минимум четыре независимых seed;
- executor и verifier независимо пересчитывают task-balanced scores и сравнивают их с заявленными значениями;
- восстановленный JSON-реестр не наследует in-process доверие без повторного ввода исходных signed artifacts;
- результат остаётся моментальным holdout с `delayMs: 0`. Ни задержанная ретенция, ни transfer не подразумеваются.

## Уточнение WorkPass534

Host-owned method-pair evaluator работает только в экспериментальном P36 lane. Даже если signed holdout подтверждает улучшение baseline/treatment, это не означает, что навык удержан или перенесён. Для этих утверждений требуется другой зарезервированный ID — `organism.learning.p36.evaluate-maturity` — и отдельная доверенная host-конфигурация с реальной delayed-retention/transfer проверкой.

## Регрессионное покрытие

`tests/p36-verified-outcome-ledger-evaluator.mjs` теперь также проверяет отказ от альтернативного treatment method и незарегистрированного семейства задач.

Команда: `npm run test:p36:verified-ledger-evaluator`. Workflow P26 Learning Validation включает этот suite, но **его выполнение на текущем HEAD не подтверждено**; успешный TypeScript typecheck тоже не подтверждён.

`main` и GitHub Release ZIP не изменялись. Production host по-прежнему должен предоставить доверенный signed-outcome ledger и собственную конфигурацию оценщика; для production-ready саморазвития дополнительно нужны независимые delayed-retention/transfer данные.
