## WorkPass36 cross-cutting integration

- **Version/schema contract:** `ReleaseContract` now matches the canonical runtime package and integration manifest (35.58.0 / schema 224); schema-223 persisted snapshots are normalized into schema 224 and covered by `release-contract-alignment-workpass36.mjs`. The top-level app-shell version remains separately named (`35.0.0-super-final21`) and is not automatically used as the runtime persistence version.

- **Shared numeric primitives:** FNV-1a and cosine similarity moved to `organism/core/NumericPrimitives.ts`; old `1e-9` squared-norm floors are kept where they affect established scores. Function-specific thresholds and distinct L1 distance remain in their original modules.
- **Unified action costs:** seven identical costs are declared in `organism/core/ActionCostPolicy.ts` and consumed by `OrganismCore`, `ParametricPolicyLearner`, `ActiveInferenceEngine` and `ContextualWorldModel`. `B2511ActiveEpistemicExperimentController` retains its different domain-specific costs because those values are not semantically equal.
- **Shared Unicode tokenizer:** `organism/core/UnicodeTokenizer.ts` consolidates Lumina/Conscio Unicode tokenization while keeping underscore/hyphen behavior opt-in, preserving existing layer-specific term boundaries.
- **Shared stable hashing:** `organism/core/StableSerialization.ts` centralizes canonical key ordering and SHA-256. `json` mode retains JSON semantics; `legacy` mode deliberately preserves older persisted fingerprint bytes, including nested `undefined` tokens. Do not replace legacy mode until persisted digest migration is planned.
- **Bounded memory maintenance:** MemoryOS2 revision history is capped at 64, reason text at 240 characters, and revision storage is part of memory-byte estimation. Restore sanitizes invalid/oversized trails.
- **Indexed memory relation discovery:** `MemorySubstrateCoordinator` uses token postings and exact-content lookups instead of repeatedly comparing all pairs; its results are differentially checked against the prior brute-force Jaccard behavior.
- **Source-history immutability:** historical ZIPs resolve through content-addressed blobs and SHA-256 manifests, not mutable active tree files. Changes to active code therefore cannot silently rewrite past versions.

## Release boundary / what is not claimed

Static and focused tests support these implementation changes, but do not demonstrate full release readiness. Still open: real local model inference and target-device latency/VRAM/RAM; independent labelled temporal holdout and retrieval promotion; action → external postcondition → reafference with no-double-credit across real providers; complete React/Vite production build and browser/Live2D E2E; clean-room restore/rollback, long soak, and release sign-off. Research/Python models and source archives are reference assets unless a tested bridge explicitly calls them.
