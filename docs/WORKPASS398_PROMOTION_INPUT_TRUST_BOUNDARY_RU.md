# WorkPass398 — защищённая граница входа для независимого продвижения P23

**Ветка:** `feature/learning`  
**Цель:** принимать решение о продвижении навыка только после безопасного чтения и независимой проверки входных данных.

## Что обнаружено

Публичный API `approveIndependentlyEvaluatedSkillCandidate` первым делом читал поля baseline/evaluation envelope обычным доступом к свойствам. В JS это может запустить getters и Proxy traps до того, как сработает хеширование и сопоставление независимой оценки. Аналогично approval-объект передавался в хранилище напрямую, где его поля читаются до проверки авторизации.

Это не позволяло внешним отчётам сразу продвинуть кандидата после WorkPass394–397, но оставляло ненужную возможность выполнить вызываемый вызывающей стороной код до отсеивания некорректного envelope.

## Реальное изменение

- `approveIndependentlyEvaluatedSkillCandidate` теперь сначала снимает проверенный plain-data snapshot с baseline и evaluation envelope. Ошибка дескриптора, getter, нестандартного объекта или недопустимой структуры приводит к закрытому отказу до чтения полей и обращения к store.
- Общий приватный финализатор передаёт хранилищу detached snapshot approval. Approval accessor не исполняется; обычную авторизацию по настроенному trusted verifier по-прежнему выполняет store.
- Добавлены регрессии для accessor в baseline, evaluation envelope и approval. Каждая проверяет, что getter не был вызван и что store не получил запрос на продвижение.
- Существующая P26 Learning Validation workflow уже включает тот же файл теста и source-path filter для P23LearningEngine, поэтому отдельный дублирующий workflow не нужен.

## Почему это важно для самообучения

Наблюдения и отчёты не должны менять состояние личности напрямую. Их следует преобразовать в ограниченные, неизменяемые данные; проверить соответствие исполняемому кандидату, задаче и среде; только затем оценивать и продвигать кандидат через явно авторизованный путь. Это связывает слой опыта/рефлексии с управляемой модификацией навыков, не смешивая диагностику и право активации.

## Проверка и ограничения

Проверка кода подтверждает, что snapshot выполняется перед доступом к полям, а новые тестовые утверждения проверяют отсутствие вызова getters. Но тесты и typecheck на фактическом Node 24 runner в этом проходе не были запущены: в доступных Actions результатах по-прежнему отсутствуют шаги и логи. Результат обучения и рост навыков не измерялись. Этот патч не является свидетельством субъективного сознания.
