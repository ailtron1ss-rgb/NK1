# WorkPass530 — ограничение полномочий оценщика саморазвития P36

**Дата:** 25 октября 2026 г.  
**Ветка:** `feature/learning`  
**PR:** [#79 → integration](https://github.com/ailtron1ss-rgb/NK1/pull/79)  
**Проверка:** код и регрессионный сценарий закоммичены; точный HEAD ещё не подтверждён CI/typecheck.

## Проблема

Резервирование имени `organism.learning.p36.evaluate-evidence` само по себе не гарантировало, что оценщик зарегистрирован доверенным окружением. Общий публичный метод `OrganismCore.registerActionTool` позволял любому вызывающему коду с доступом к Core попытаться занять этот ID собственным executor/verifier callback. Это размывало границу между «хост проверил результат» и «обычный адаптер назвал себя оценщиком».

## Что изменено

### Конфигурация доверенного хоста

Добавлено поле `OrganismConfig.p36IndependentEvaluator` — construction-time capability для адаптера, который передаётся приложением при создании `OrganismCore`. Core регистрирует этот адаптер под фиксированным `P36_EXTERNAL_EVIDENCE_TOOL_ID`, не позволяя конфигурации выбирать произвольный ID.

Перед регистрацией проверяется, что:
- адаптер не является destructive-tool;
- присутствуют исполнитель `execute` и verifier `verify`;
- указан внешний источник наблюдения с непустыми `sourceId`, `sourceClass`, `channel` и `independenceKey`;
- оценщик не требует ключа идемпотентности, поскольку этот зарезервированный маршрут — чтение/оценка, а не мутация внешнего мира.

Некорректная конфигурация завершается fail-closed с `p36-independent-evaluator-host-config-invalid`.

### Публичный реестр

`OrganismCore.registerActionTool` теперь явно отклоняет зарезервированный ID с `reserved-p36-evaluator-must-be-configured-at-core-construction`. Остальные зарегистрированные инструменты продолжают работать по прежнему пути.

Это граница конфигурации хоста, не криптографическая аттестация: production-запуск должен сам предоставлять доверенную конфигурацию, не собранную из данных агента или пользователя.

### Регрессионное покрытие

`tests/p36-integration.mjs` теперь:
- регистрирует fixture-оценщик через construction-time `p36IndependentEvaluator`;
- проверяет, что зарезервированный инструмент присутствует после инициализации;
- проверяет, что попытка подменить его через публичный `registerActionTool` отклоняется;
- продолжает проверять decision-linked внешнее свидетельство, отказ на несвязанном решении, отдельный путь зрелости и сохранение результата.

Предыдущий WorkPass529 отделил `kind: 'developmental-outcome'` от обычного baseline/treatment/holdout-свидетельства и убрал доверие к `verifiedNow` из общих world/reward feedback.

## Текущая граница готовности

**Сделано в коде:** доверенный construction-time вход оценщика, блокировка публичной регистрации зарезервированного ID, обновлённый Core integration fixture и документированный handover.

**Пока не подтверждено:** выполнение тестов P36, TypeScript typecheck и exact-HEAD GitHub Actions. В текущей сессии GitHub не вернул проверяемый запуск для HEAD; заявление о прохождении тестов не делается.

**Ещё не сделано:** настоящий production host-owned evaluator, подключённый приложением под этот конфигурационный слот, и независимый end-to-end замер baseline vs treatment на frozen holdout с delayed retention и transfer. Тестовый evaluator — только fixture и не является производственным источником доказательств.

`main` и GitHub Release ZIP не изменены. Новых runtime-зависимостей не добавлено.
