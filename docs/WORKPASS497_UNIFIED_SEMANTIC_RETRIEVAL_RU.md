# WorkPass497 — единый маршрут семантического извлечения в когнитивном цикле

**Дата:** 27 октября 2026 года  
**База:** `workpass70-source`, SHA `974fbdba737c5e5de49a2b0804a81a5ae39c696b`  
**Область:** маршрут чтения памяти в `OrganismCore`; алгоритм ранжирования не изменяется.

## Дефект

Первичный текстовый вход уже вызывал `MemoryFabric.retrieveForCognition()`, который сначала получает лексический результат, а семантический поиск запускает только при явной настройке, с ограниченным бюджетом и fallback при timeout/ошибке. Но второй путь — пустое наблюдение с активной внутренней целью — обходил этот адаптер и синхронно вызывал `MemoryFabric.retrieve()`.

Кроме того, прежняя ветка `else` могла извлекать воспоминания даже при `cognitiveExecutionPlan.run.memory === false`, поскольку выключенный маршрут попадал в fallback, а не в пустой пакет.

## Исправление

Теперь оба разрешённых пути используют один `retrieveForCognition()` контракт. Если execution plan выключил память, `OrganismCore` передаёт пустой список. Если первичный запрос уже извлечён, повторное извлечение не выполняется; внутренние цели используют bounded adapter.

Добавлен `test:workpass497:semantic-retrieval-route`, подключённый к `workpass71-validation.yml` и `audit:nk1-integration-closure`. Тест закрепляет routing, выключение памяти, opt-in семантики, foreground budget и лексический fallback.

Это подтверждение целостности маршрута, а не прироста recall. Для оценки полезности по-прежнему нужен независимый RU/EN holdout; `main` и Release ZIP не меняются.
