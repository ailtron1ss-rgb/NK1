# NK1 Memory/Recall — протокол независимых разговоров и кластерной оценки

**Дата:** 30 октября 2026 года  
**Протокол:** `memoryos2-benchmark-v2-conversation-clustered-bootstrap`  
**Рабочая ветка:** `work/memory-recall-closure-2026-10-29`  
**PR:** #389, draft, без слияния

## 1. Почему изменён протокол

В длинной истории один пользовательский разговор может порождать много связанных вопросов. Эти вопросы не являются независимыми наблюдениями: они используют один контекст, одни события и часто одни и те же фрагменты памяти. Обычный bootstrap по отдельным вопросам может вести себя так, будто десятки вопросов из одного диалога — десятки независимых источников доказательств.

NK1 теперь пересэмплирует целые исходные разговоры как кластеры. Сравнение baseline и candidate остаётся парным: при каждом bootstrap draw обе ветви получают те же выбранные conversation-группы и все вопросы внутри каждой выбранной группы. Поэтому разница candidate-vs-baseline не разрушается случайным рассогласованием тестовых примеров.

Это соответствует общей методологии кластерного вывода: зависимость внутри группы допускается, а число кластеров и распределение размеров групп должны быть явно показаны. Сам по себе большой объём вопросов не компенсирует малое число независимых разговоров.

## 2. Контракт входных меток

JSONL row может включать:

```json
{
  "id": "q-00017",
  "query": "Что изменилось в моих целях после второй беседы?",
  "relevantIds": ["memory-42", "memory-57"],
  "split": "holdout",
  "answerable": true,
  "language": "ru",
  "category": "multi-session",
  "conversationId": "hmac-sha256:9a1d...e70b"
}
```

Правила:

1. `conversationId` — стабильный псевдоним **исходного диалога целиком**, объединяющий все его сессии и продолжения. Нельзя создавать отдельный ID для каждого вопроса или каждой сессии одной истории.
2. Внешний пользовательский ID, имя, текст диалога и другие PII не передаются в benchmark report. Для воспроизводимой разметки следует применять HMAC-SHA256 с секретным salt, хранящимся вне репозитория, либо другой внутренний стабильный необратимый псевдоним.
3. Все вопросы одного разговора должны попасть только в один split. Если одинаковый `conversationId` встречен в train и holdout, набор непригоден для promotion evidence.
4. Любая запись категории `multi-session` должна иметь непустой `conversationId`. Отсутствие группировки не должно незаметно превращать задачу multi-session в набор независимых одиночных вопросов.
5. Метка `answerable:false` требует пустой `relevantIds`; отвечаемый вопрос требует хотя бы одну валидную релевантную запись.
6. Язык и категория задаются разметчиком. Их нельзя выводить из результата retrieval или ответа модели.

CLI сохраняет `category` и `conversationId` из JSONL в benchmark. Ранее `category` терялась при CLI parsing, несмотря на поддержку в benchmark API; этот разрыв закрыт.

## 3. Кластерный paired bootstrap

Для набора из (G) независимых групп:

1. Сформировать список разговоров, содержащих отвечаемые holdout-вопросы.
2. Случайно выбрать (G) групп с возвращением.
3. Для каждого выбранного разговора включить **все** его вопросы. Повторно выбранный кластер повторно вносит весь свой набор вопросов.
4. На одной и той же выборке вопросов вычислить baseline и candidate; получить paired delta Recall@k или MRR.
5. Повторить процедуру заданное число bootstrap-итераций и получить percentile interval.

Для явно неотвечаемых вопросов применяется отдельная параллельная группировка и отдельная оценка unsupported retrieval / correct abstention. Она не увеличивает число независимых отвечаемых групп, используемых для gate Recall uplift.

Если `conversationId` не задан для обычных одиночных задач, отдельный query ID становится fallback-кластером. Если группировка задана частично, набор блокируется для promotion. При наличии conversationId все вопросы одного источника группируются вместе.

### Чего этот метод не делает

- Не создаёт дополнительные независимые разговоры из одного источника.
- Не доказывает качество на production corpus без лицензированной независимой разметки.
- Не делает вывод об эффективности retrieval только по синтетическим тестам.
- Не заменяет human review и не изменяет живую память.
- Не исправляет неверные ground-truth labels: для этого по-прежнему нужны provenance, labeling protocol и проверка релевантных ID.

## 4. Диагностика размера кластеров и влияния отдельных диалогов

В dataset integrity report публикуются только агрегаты, не исходные conversation IDs:

- количество групп и вопросов;
- минимальный, медианный, средний и максимальный размер группы;
- доля самого крупного разговора в совокупности вопросов;
- отношение максимального размера группы к медианному;
- отдельная статистика для answerable и unanswerable holdout.

Дополнительно включён leave-one-conversation-out sensitivity analysis. Он последовательно исключает один исходный разговор, пересчитывает paired delta и сообщает диапазон результатов, максимальный сдвиг и число случаев, когда знак дельты меняется.

Это **диагностика влияния**, а не доверительный интервал. Если знак улучшения меняется после удаления одного разговора, результат нестабилен и требует дополнительного независимого набора, даже если общая bootstrap-точечная оценка выглядит благоприятно.

Сами значения `conversationId` не выводятся ни в диагностике, ни в fingerprint report; в fingerprint включается каноническое значение псевдонима, необходимое для воспроизводимости и контроля утечки.

## 5. Порог независимых доказательств

Кодовый hard floor — не менее 8 независимых отвечаемых holdout-разговоров в общем наборе и отдельно в каждом обязательном языке при включённой RU/EN stratification. Этот порог блокирует очевидно недостаточную выборку, но **не является гарантией надёжного статистического вывода**.

Для реального NK1 evaluation следует целиться как минимум в 20–30 независимых диалогов на язык, а лучше — существенно больше, с разными пользователями/контекстами/типами событий и контролируемой неоднородностью размеров групп. Это операционная рекомендация для проекта, а не универсальная математическая граница. При малом числе кластеров обычные bootstrap-приближения могут быть ненадёжными; увеличение количества bootstrap draws само по себе не исправляет недостаток независимых кластеров.

Обязательные выводы при оценке:

- число независимых разговоров (G), отдельно от числа вопросов (N);
- распределение размера кластеров;
- RU и EN метрики отдельно;
- Recall@k, MRR, precision, coverage;
- false abstention и unsupported retrieval;
- stale, future, quarantined, dormant и invalid result counts;
- latency p50/p95 и стоимость извлечения;
- cluster leave-one-out sensitivity;
- dataset/corpus/configuration fingerprints и provenance/licence.

Ни один результат не продвигается автоматически. Promotion gate остаётся отдельным от запуска benchmark, а benchmark работает на изолированном snapshot.

## 6. Встроенные проверки

`runtime/neuro-kurisu/tests/memory-retrieval-experiment.mjs` теперь проверяет:

- вопросы одного диалога пересэмплируются одним кластером;
- множество вопросов из малого числа разговоров не удовлетворяет минимальному независимому sample gate;
- train/holdout leakage по conversationId отклоняется;
- multi-session без conversationId отклоняется;
- размеры групп и largest-cluster share вычисляются корректно;
- leave-one-conversation-out диагностика публикуется и не маркируется доверительным интервалом;
- conversationId участвует в dataset fingerprint;
- CLI сохраняет language/category/conversationId и отвергает пустой или malformed group ID;
- multi-seed report сохраняет grouped integrity и sensitivity diagnostics на уровне каждой seed-run записи.

Проверка типа остаётся отдельной от теста алгоритма. Целевой проход: `npm run typecheck`, `npm run test:memory-retrieval-experiment`, затем полный `npm run test:memory-acceptance` и integration closure.

## 7. Исследовательская основа

- LongMemEval выделяет multi-session reasoning, temporal reasoning, knowledge updates и abstention как самостоятельные способности памяти.
- LoCoMo использует очень длинные диалоги (в среднем около 588 ходов, 27 сессий и 16.6K токенов на разговор), что показывает, почему многократные вопросы из одного разговора нельзя бездумно считать независимыми.
- Руководство MacKinnon, Nielsen и Webb по cluster-robust inference подчёркивает роль числа кластеров и неоднородности размеров групп; при малом числе кластеров стандартные приближения могут давать ненадёжный результат, поэтому bootstrap и отчёт о размере кластеров важны.

## 8. Ограничения текущей реализации

- Cluster bootstrap и delete-one analysis — инструментальные улучшения оценки, но не замена специализированной процедуре wild cluster bootstrap для регрессионных моделей. NK1 оценивает парные метрики retrieval на фиксированных размеченных вопросах.
- Hard floor в 8 групп — защитная нижняя граница, а не endorsement качества.
- Псевдонимизация идентификаторов остаётся обязанностью dataset-preparation pipeline; репозиторий не может доказать, что внешняя разметка действительно анонимизирована.
- Позитивный production recall uplift остаётся неподтверждённым до появления лицензированного immutable RU/EN holdout с независимой разметкой.
