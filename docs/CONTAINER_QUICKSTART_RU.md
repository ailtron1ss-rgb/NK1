# Запуск Neuro Kurisu через Docker Compose

Этот вариант поднимает один контейнер с Node.js 24 runtime, локальным gateway, Vite UI и Python research bridge; состояние сохраняется в named volume `nk1-state`. По умолчанию веб-порт привязан только к loopback хоста, поэтому UI доступен на этой машине по адресу `http://127.0.0.1:8080`.

## Требования

Нужны Docker Engine и Docker Compose v2. Репозиторий не должен содержать секреты в исходниках; `.env` файлы исключены из образа через `.dockerignore`.

## Первый запуск

```sh
docker compose up --build
```

На этапе сборки образа устанавливаются заблокированные Node-зависимости (с dev-инструментами для Vite). Контейнер запускается непривилегированным пользователем `node`, а writable volume подготовлен с корректным владельцем. На первом старте контейнер  Если `app/dist/index.html` отсутствует, лаунчер выполняет `npm --prefix app run build:web` (Vite build без миграции базы) и только затем запускает preview/gateway. В другом терминале:

```sh
docker compose ps
docker compose logs -f neuro-kurisu
```

Остановить контейнер без удаления данных: `docker compose down`. Состояние находится в volume `nk1-state`; удалить его нужно явно через `docker compose down -v`.

## Необязательные Torch-исследования

Основной runtime и HTTP research bridge запускаются без PyTorch. Некоторые CPU research probes из `research/` импортируют Torch. Чтобы включить их в образ, выполнить первый билд так:

```sh
INSTALL_RESEARCH_TORCH=true docker compose up --build
```

Это существенно увеличивает размер и время сборки. Повторный запуск с другим значением build-аргумента пересобирает образ.

## Сеть и безопасность

Gateway намеренно слушает `127.0.0.1` при обычном `npm start`. В контейнере Compose явно задаёт `SUPER_GATEWAY_HOST=0.0.0.0`, а публикация порта ограничена `127.0.0.1:8080` на хосте. Чтобы открыть UI другой машине, отдельно измените публикацию порта и оцените сетевую аутентификацию/доступ; не публикуйте gateway на внешнюю сеть по умолчанию.

## Что ещё нужно для production

Этот Compose-файл — повторяемый путь запуска, но сам по себе не доказывает production-готовность: необходимы реальные секреты внешних LLM/API, если они используются, проверка persistent-store backup/restore, полноценные probes для всех upstreams и exact-head Docker/CI smoke. Фактические статусы проверок заносятся в `CHANGELOG.md`; успешная сборка образа пока не утверждается, пока соответствующий CI job не завершится.
