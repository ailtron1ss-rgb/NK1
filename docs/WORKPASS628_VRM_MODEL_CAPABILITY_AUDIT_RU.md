# NK1 WorkPass 628 — VRM capability audit and model interoperability

Дата: 2026-10-30  
Направление: Aspect 05 — VRM / VRMA Runtime  
База изменений: `feature/embodiment-model-hardening-2026-10-29`  
Цель: сделать фактические возможности импортированной модели явными для NK1 до того, как моторный контроллер начнёт использовать её как полноценное тело.

## 1. Проблема

Успешный GLB/VRM parse ещё не означает, что модель пригодна для полного управления телом. В модели могут отсутствовать:
- обязательные humanoid-кости и отдельные сегменты конечностей;
- кисти и пальцы;
- SkinnedMesh и корректная деформация;
- выражения лица и viseme;
- LookAt;
- SpringBone joints;
- анимационные клипы.

Ранее интерфейс показывал преимущественно факт загрузки и наличие нескольких распознанных костей. Это создавало риск переоценить совместимость модели.

## 2. Что добавлено в WorkPass 628

### Runtime capability inspection
Новый модуль `app/src/components/avatar/vrmModelCapabilities.ts`:
- описывает полный словарь основных VRM humanoid bones, включая кисти и пальцы;
- проверяет доступность костей через официальный `getNormalizedBoneNode`, а не только по именам узлов;
- определяет полноту core, верхней и нижней частей тела, кистей и пальцев;
- обнаруживает ExpressionManager, blink и доступные viseme;
- фиксирует LookAt, SpringBone joints и embedded clips;
- считает meshes, SkinnedMesh и bones;
- присваивает осторожную категорию `full | body | limited | static`;
- возвращает предупреждения о реально отсутствующих возможностях;
- не мутирует VRM runtime и не падает на некорректных optional manager API.

### Import feedback
`Avatar3DStage` теперь показывает компактную capability-сводку после успешного импорта: количество костей, SkinnedMesh, expressions, viseme, SpringBone и наличие LookAt. Первое предупреждение выводится рядом со сводкой, чтобы пользователь не принимал статическую модель за полностью управляемое тело.

### Regression coverage
Добавлен `app/scripts/avatar-vrm-model-capabilities.test.mjs` и команда:
`npm run test:avatar-vrm-model-capabilities`.

Проверяются:
1. Полный набор костей и полный профиль.
2. Отсутствующие конечности, кисти, пальцы и физика.
3. Частично пригодный rig.
4. Обычный GLB без VRM runtime.
5. Ошибочные optional manager API и безопасное продолжение инспекции.

## 3. Границы этой работы

- Capability report — не автоматический ремонт рига и не доказательство качества skin weights.
- Наличие VRM ExpressionManager не доказывает художественное качество blend shapes.
- Наличие VRMA клипа не доказывает, что он ретаргетирован правильно для конкретного тела.
- `full` означает наличие требуемых структурных возможностей, но не заменяет реальный визуальный E2E.
- Нельзя автоматически объявлять лицензию подтверждённой по метаданным VRM.

## 4. Следующие работы Aspect 05

### P0 — корректность runtime
- Проверить актуальный CI на точном HEAD.
- Прогнать model validation и VRMA validation на повреждённых и пограничных GLB.
- Проверить гонки при замене VRM во время загрузки VRMA.
- Проверить освобождение VRM/VRMA ресурсов и IndexedDB recovery.
- Подтвердить VRM 0.x и VRM 1.0 реальными fixture-моделями.

### P1 — полная совместимость тела
- Использовать официальный VRM normalized humanoid API как источник истины для всех суставов.
- Добавить semantic bone capability matrix для torso, arms, hands, fingers, legs, feet и toes.
- Добавить ретаргетинг на skeleton profile, а не эвристику только по имени клипа.
- Добавить проверку bind pose, skinning и масштаба.
- Проверять совместимость VRMA с целевым VRM до активации клипа.

### P1 — выражения и физика
- Учитывать VRM expression overrides (mouth/blink/lookAt) при смешивании.
- Проверять конфликт VRMA expression tracks с речевыми viseme.
- Отслеживать SpringBone groups, joints и collider groups.
- Предусмотреть graceful fallback при отсутствии выражения или физического компонента.

### P2 — библиотека тел
- Каталог моделей с capability fingerprint, автором, источником и лицензией.
- Раздельные профили тела и внешнего вида.
- Кэшировать проверку по fingerprint файла.
- Поддержать выбор тела без потери текущего когнитивного состояния NK1.

## 5. Критерии завершения Aspect 05

- Импорт VRM 0.x и VRM 1.0 проверен на реальных моделях.
- GLB без VRM корректно классифицируется как ограниченная модель.
- Ни один отсутствующий сустав не маскируется как доступный.
- VRMA не активируется на несовместимом теле без явного fallback.
- Expression/viseme/LookAt/SpringBone имеют отдельные capability flags.
- Модель можно заменить и восстановить после перезапуска без потери runtime ресурсов.
- Визуальные проверки пройдены на desktop и Android.
- Лицензионные метаданные остаются предупреждением, а не автоматическим разрешением.

## 6. Статус

В этом WorkPass реализован capability audit и пользовательская сводка. Это повышает достоверность определения возможностей импортируемого тела, но не завершает полный humanoid motor controller, физику одежды, ретаргетинг и визуальный E2E.

Проверять статус CI нужно по точному HEAD ветки; отсутствие результата или незавершённый workflow не считать успешной проверкой.
