# Open-source integration review — WorkPass39 (2026-10-14)

## Decision policy

The objective is one coherent Neuro-Kurisu organism, not a stack of frameworks. Reuse source code only after reviewing repository state, license, dependencies, runtime boundary, behavioral semantics, and hardware/deployment cost. Preserve upstream provenance and isolate incompatible runtimes behind typed adapters. This pass did not copy external repositories wholesale: the container's outbound Git/DNS connection is unavailable, so source code could not be cloned for byte-level review. The repositories below were reviewed through their public GitHub pages/documentation. Their patterns informed implementation; a candidate code-port remains explicitly pending whenever full source/license/dependency review is not complete.

## Implemented from the review

1. **Evidence identity:** `ExternalObserverFabric`, `ExternalEvidenceTrust`, and `EvidenceFirewall` use SHA-256 identities for new external observations. Existing FNV-based ids are preserved on restore/re-observation to avoid duplicate evidence and to maintain continuity.
2. **Confidence-aware global workspace:** `CognitiveNetworkBus` now ranks each signal using score, confidence, specialist weight, attention budget, and a bounded energy penalty. Confidence and energy were previously present as fields but not used in winner selection.
3. **One cognitive-architecture owner map:** `CognitiveArchitectureMap` identifies the actual module owner for organism state, writable memory, final decision, side-effect execution, evidence verification, and research promotion. The map is read-only metadata, not a second brain/runtime.
4. **UI surface:** Runtime Atlas has a dedicated Brain Architecture panel with subsystem owners, data products, dependencies, and typed flow edges, plus a collapsed raw JSON view.
5. **Affect → global workspace → action candidate:** the live `EmotionAppraisalEngine` output is now a typed `affect` specialist signal with confidence, tendency, arousal, stress, salience, feeling intensity, bodily focus, and interoceptive mismatch. Only when the signal wins a workspace slot can it add a small capped action-tendency prior; P69 remains the final decision owner. A real `OrganismCore` cycle test distinguishes stress/anxiety (arousal ≈0.85) from calm (≈0.19).
6. **Salience evidence fusion:** same-specialist salience signals are fused before workspace selection so the signal from the sensory-perception event and the general salience specialist do not overwrite each other's provenance/evidence. Disabling the cognitive network now removes stale prior-cycle broadcasts from action scoring.
7. **Immutable source-history repair:** changed active versions of `CognitiveNetworkBus` and `ExternalEvidenceTrust` no longer act as the source of historical archives. Old bytes were re-created from WorkPass38 and stored in content-addressed blobs; 8 manifest references were redirected. The source archives validate 8,512/8,512 members and the 2026-10-06 snapshot validates 10,427 members / 18,935 logical content references.
8. **Exact-duplicate optimization is provenance-aware:** duplicated content-addressed blobs were consolidated only after all affected manifests resolved to the shared hash-checked path; root historical reports are retained as short pointers to canonical documents. Identical Live2D copies served by different deployment paths and distinct source snapshots were not deleted.

## Upstream code-port decisions (review refreshed 2026-10-14)

- The current Mem0 README describes multi-signal retrieval (semantic, BM25, entity matching) and temporal reasoning, but its hosted benchmark includes optimizations unavailable in the open-source package. Those claims are not taken as proof for Neuro-Kurisu; the local temporal retrieval fixture has `recallDelta=0`, so no retrieval implementation is promoted without an independently labelled holdout. (Upstream: https://github.com/mem0ai/mem0)
- The OpenAI Agents SDK documents small primitives for handoffs, sessions, guardrails and tool lifecycle checks. Neuro-Kurisu already owns a canonical `ActionGateway`; importing another orchestrator would duplicate authority. We use the pre/post-effect guardrail pattern, not the SDK runtime itself. (https://github.com/openai/openai-agents-python)
- LangGraph persistence separates scoped checkpoints from cross-session long-term stores. This matches the project's split between action/recovery persistence and the sole writable `MemoryOS2`; there is no reason to install a second memory owner. (https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/persistence.mdx)
- Microsoft has positioned Agent Framework as the successor for new work while AutoGen is in maintenance mode. AutoGen-specific new dependencies are therefore not recommended. (https://github.com/microsoft/autogen ; https://github.com/microsoft/agent-framework)
- `llama.cpp` remains a sensible local-inference backend candidate for modest hardware, but actual integration depends on target-GPU VRAM/latency tests and model/runtime license review, not just the presence of a REST endpoint. (https://github.com/ggml-org/llama.cpp)

## Not promoted / future work

- No new vector store or third-party orchestration dependency is added in this pass. There is no measured evidence that it improves the current project more than it costs in dependencies, memory, portability and integration risk.
- A local inference provider (llama.cpp or compatible provider) needs a typed common contract, license/model provenance, explicit device capability detection and real target-hardware benchmarks before integration.
- More detailed affective, social and self-model coupling should consume verified observations and temporally-attributed outcomes. Merely increasing subsystem counts or adding language-model descriptions is not an improvement.
- Full source downloads / byte-level upstream audits remain pending due unavailable container-side Git/DNS. URLs are retained above to make the exact candidates reproducible; no claim is made that their source files were downloaded into this archive.
