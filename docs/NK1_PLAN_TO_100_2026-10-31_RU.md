# NK1 / NeuroCore — план доведения до 100% (сводный, 2026-10-31)

Дополняет `NK1_MASTER_PLAN_TO_100_2026-10-30_RU.md`. Здесь — единая картина по аспектам, фактическое состояние и прогресс, анализ веток и полный рабочий план, включая смену тела 2D / 2.5D / 3D.

## 0. Главный вывод (то, что реально блокирует «100%»)

Проблема не в нехватке модулей. Модулей и контрактов много. Проблема в трёх вещах:

1. **Спагетти из PR.** На `workpass70-source` открыто **187 PR** (132 draft, 56 ready), почти все с одним и тем же базовым коммитом. Дублирование: 6+ PR по embodiment/motor, 4+ по 2.5D/depth, 3+ по VRM, 21 по learning. Ни один не влит. Это не «прогресс», это замороженный прогресс.
2. **Контракт ≠ интеграция.** Многие «готовые» аспекты — это проверенный чистый модуль, который **никто не вызывает** из runtime/UI. Пример этой сессии: `embodimentSwitch.ts` был протестирован, но `AvatarStage.tsx` его не использовал (исправлено в PR #473). `depthRigRendererAdapter.ts` до сих пор не импортируется нигде.
3. **Доказательных ворот нет.** Разрыв «72% автопроверки vs 17% поля» — это отсутствие browser/Android E2E, soak, production build и релиза из текущего source.

**Формула доведения до 100%:** закрыть доказательные ворота, а не добавить модули. Каждый аспект считается закрытым только когда (а) модуль вызывается из runtime/UI, (б) есть зелёная автопроверка, (в) есть подтверждение на реальном устройстве/браузере.

## 4. Смена тела 2D / 2.5D / 3D — целевое состояние и что сделано

### 4.1 Что уже реально есть

- `embodimentSwitch.ts` — версионированный `SemanticBodyState`, capability-aware switch plan, unsupported-список, общий pose blend, монотонный прогресс. Тесты 5.
- `embodimentCoordinator.ts` — транзакционный handoff (prepare→apply→verify→commit/rollback) с receipt/verification. Тесты.
- `embodimentUiBridge.ts` (**новое, PR #473**) — мост snapshot→SemanticBodyState + capability-таблица 4 рендеров + bounded crossfade; **реально подключён в `AvatarStage.tsx`**. Тесты 9.
- Live2D: `live2d_intent_ack` (revision-bound, `complete:false`).

### 4.2 Три тела: честный статус

| Тело | Что есть | Что мешает 100% |
|---|---|---|
| **2D** | Live2D Cubism (moc3, 8 выражений, 5 клипов), 32 спрайта, SVG original | больше motion/expression; реальный garment swap; browser+Android E2E |
| **2.5D** | `depthRig.ts` контракт + валидатор + Three-adapter + springs | **adapter не вызывается**; нет production layered art (PSD/ORA); нет occlusion-масок |
| **3D** | Three.js stage, процедурное тело, импорт VRM/GLB, `MotorRigProfileV1`, `solveTwoBoneIK` | нет легального VRM-рига Курису; нет VRM spring physics/MToon; нет E2E |

### 4.3 План по 2D/2.5D/3D (этапы, каждый даёт рабочий результат)

**E1 — Реальный adapter lifecycle (P0).** Реализовать 4 адаптера (`Live2DAdapter`, `Depth2DAdapter`, `VRM3DAdapter`, `Sprite2DAdapter`) с `prepare/apply/verify/dispose`, подключить `EmbodimentSwitchCoordinator` в `AvatarStage`. Каждый adapter возвращает `AdapterApplyReceipt` только при измеренном readback. **Критерий:** переключение тела не теряет emotion/gaze/speech/wardrobe; старый рендер жив до успешного verify; rollback при ошибке. **Проверка:** unit + интеграционный round-trip 2D↔2.5D↔3D на одном snapshot.

**E2 — Подключить 2.5D к render-пути (P0).** Вызвать `applyDepthRigWorldPoseToLayers` из `Avatar3DStage`/нового `Depth2DStage`; capability manifest из фактических слоёв. **Критерий:** 2.5D-рендер виден и реагирует на позу; unsupported-слои отчитываются. **Проверка:** рендер-тест + browser smoke.

**E3 — Crossfade и качество перехода (P1).** Crossfade 150–350 ms (сейчас 220), удержание последней подтверждённой позы, синхронизация viseme по единому speech clock. **Критерий:** нет скачка в rest pose; нет рестарта речи; замерены handoff latency и pose discontinuity.

**E4 — 3D риг (P1).** Легальный VRM/glTF риг Курису (humanoid, morphs, look-at, spring bones, IK), VRM runtime (spring physics, MToon, retargeting). **Критерий:** загруженный риг даёт skeleton/IK/look-at; capability manifest отражает фактический риг.

**E5 — E2E и soak (P2).** Browser E2E (переключение во время речи/жеста/эмоции/загрузки модели), Android E2E (low-memory, WebGL loss, orientation, background/foreground), soak ≥30 мин циклических переключений без утечек RAF/WebGL/audio/IndexedDB. **Критерий:** метрики handoff latency, dropped frames, speech-clock drift, rollback rate, unsupported-channel rate в норме.
