## WorkPass80 — восстановление целостности при загрузке snapshot

После входной валидации обучения выявлен соседний путь загрязнения: `restore()` принимал сохранённые веса/смещения и диагностические поля без надёжной обработки `NaN`/Infinity. Такой snapshot мог повторно загрязнить предсказания даже после исправления входа обучения.

### Кодовые изменения

- `restore()` заменяет нечисловые и бесконечные веса/смещения на безопасный ноль; конечные значения ограничиваются существующим диапазоном [-4, 4].
- Невалидный счётчик обновлений сбрасывается в 0; диагностические показатели нормализуются в конечный диапазон [0, 1]; некорректное время последнего обучения сбрасывается в 0.
- Расширена регрессия: повреждённый snapshot с NaN/Infinity/отрицательным счётчиком должен восстанавливаться в конечное состояние, при этом обычное валидное обучение остаётся доступным.
- Это закрывает путь повторного внесения нечисловых параметров через persisted state; не доказывает улучшение качества обучения.

### Проверка

- Тестовый сценарий добавлен, но в этой сессии не исполнялся; PASS не заявляется.
- Перед слиянием необходимы целевые тесты и typecheck в Node >=22.12.0, затем существующие P26 regression tests.
- Пороговые значения и поведение восстановления следует проверять на реальных исторических snapshots, прежде чем менять схему или выполнять массовую миграцию.


## WorkPass81 — атомарная проверка пакетного обучения

При просмотре соседнего пути обучения обнаружен риск частичного обновления: прежний `trainBatch()` применял образцы по одному, поэтому ошибочный более поздний элемент мог вызвать исключение после изменения модели предыдущими элементами. Теперь пакет предварительно проверяется целиком: тип каждого образца, идентификатор действия, конечность числовых полей и наличие структуры состояния `needs`. Только после успешной проверки начинается обучение.

В регрессионный тест добавлены два сценария: плохое состояние во втором элементе и нечисловая цель во втором элементе. Оба должны приводить к отклонению без частичного изменения snapshot. Это гарантирует атомарность именно этапа входной проверки; это не транзакция на произвольные ошибки выполнения внутри цикла обучения.

Проверка в живом Node-окружении по-прежнему не выполнена. Не объявлять PASS до CI/локального исполнения.


## WorkPass82 — детерминированный benchmark обучения и восстановления

Добавлен `tests/p26-learning-recovery-benchmark.mjs` и команда `npm run test:p26:learning-recovery-benchmark`. Это первый исполняемый кандидат на измерение поведения, а не только корректности входов. Он фиксирует четыре сценария:

1. **Online learning:** одинаковая положительная обратная связь должна сдвинуть предсказание к целевому значению.
2. **Task reversal / repair:** после смены цели на противоположную предсказание должно заметно развернуться.
3. **Frozen no-learning control:** замороженная модель должна сохранять предсказание, веса, bias и счётчик обновлений.
4. **Replay-retention probe:** обучение на втором ортогональном шаблоне записывает изменение предсказания первого шаблона (забывание/удержание), а также изменение активной цели. Это диагностический показатель, а не обещание отсутствия забывания.

Скрипт печатает метрики в JSON для сравнения последующих изменений. Пороги в сценариях намеренно ограничены базовым smoke-уровнем: они проверяют движение в ожидаемом направлении, но не являются доказательством полезности политики в реальном мире. Перед использованием как quality gate требуется живой запуск, повторяемость, несколько seed/порядков и независимые held-out задачи.

**Статус:** код и npm-команда добавлены; в этой среде Node/TypeScript тест не исполнялся. Ни один результат benchmark не заявляется как PASS.


## WorkPass83 — строгая проверка persisted freeze и матрица порядка обучения (2026-10-21)

### Реальные изменения

1. **ParametricPolicyLearner.restore()** теперь восстанавливает frozen только при буквальном boolean true. Ранее строка "false" была бы truthy в JavaScript и могла неожиданно заморозить обучение после загрузки повреждённого/несовместимого snapshot.
2. **p26-learning-input-integrity.mjs** получил регрессию для строки "false"; ожидаемое восстановленное состояние — frozen === false. Добавлена проверка рядом с уже существующими тестами повреждённых весов, bias, diagnostics, счётчика и времени.
3. **p26-learning-continual-matrix.mjs** — новый детерминированный эксперимент на трёх семействах признаков и трёх порядках обучения. Он записывает абсолютную ошибку по каждой задаче и среднюю ошибку каждого порядка, вычисляет разброс чувствительности к порядку, проверяет конечность/границы параметров и отдельно проверяет восстановление после намеренно ошибочной обратной связи.
4. В package.json добавлен запуск npm run test:p26:learning-continual-matrix.

### Границы вывода

Матрица синтетическая и небольшая: она выявляет регрессии и зависимость от порядка, но не является бенчмарком автономного поведения, не измеряет реальную пользовательскую пользу и не заменяет независимый holdout. Численные результаты не заявляются, потому что выполнение скрипта в этом проходе не подтверждено. Следующий обязательный шаг — выполнить на Node >=22.12 typecheck, input-integrity, recovery benchmark, continual matrix и test:p26:true-learning, сохранить сырые JSON-метрики, а затем расширить набор несколькими независимыми наборами задач и baseline replay/no-learning.
