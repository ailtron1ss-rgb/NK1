## Выводы

1. Репозиторий нельзя безопасно консолидировать массовым merge всех веток: 627 веток включают независимые эксперименты, исторические базовые линии, повторные rebases, draft-работу и уже заменённые реализации.
2. Наличие ветки без открытого PR не означает, что её код не нужен или что ветка устарела: она может быть уже интегрирована, закрыта без merge, сохранена как эксперимент или содержать единственную реализацию.
3. Наличие открытого PR не означает готовность к слиянию. Из 189 открытых PR 131 помечен Draft; у многих веток базовый SHA отстаёт от текущей канонической линии.
4. Открытые PR направлены не только в канонический source: 93 PR используют другие базовые ветки. Их нельзя сливать напрямую в `workpass70-source` без проверки ancestry и diff.
5. Успешные CI-проверки старого SHA не подтверждают новый head после переноса или rebase.

## Правило консолидации

Каждую ветку обрабатывать отдельно по следующему протоколу:

1. Зафиксировать head SHA, базовую ветку и дату последнего изменения.
2. Сопоставить с `workpass70-source`: ancestry, ahead/behind, список изменённых файлов и diff.
3. Найти PR (открытый и закрытый), проверить merge outcome и определить, не перенесены ли изменения уже другим PR.
4. Классифицировать ветку: `CANONICAL`, `INTEGRATED`, `READY`, `NEEDS_REBASE`, `DRAFT`, `SUPERSEDED`, `EXPERIMENT` или `REVIEW_REQUIRED`.
5. Для полезного изменения перенести только необходимые коммиты/файлы на свежую ветку от текущего `workpass70-source`; не переносить устаревшую историю целиком.
6. После переноса запустить профильные тесты и полный обязательный набор для затронутых контрактов; зафиксировать результаты на точном итоговом SHA.
7. Только после успешной проверки открыть/обновить PR и выполнить merge с ожидаемым head SHA.
8. Удалять ветки только после доказательства, что нужные изменения интегрированы или ветка явно признана ненужной. Не удалять исторические артефакты автоматически.

## Канонические линии

- `workpass70-source` — исходная рабочая линия кода NK1; новые runtime-интеграции должны попадать сюда после профильных проверок.
- `main` — отчёты, Release-процессы и документация; не использовать как замену source-ветке.
- `integration` и исторические feature/fix/workpass ветки — источники отдельных изменений, а не самостоятельные конкурирующие канонические версии.

## Отдельные блокирующие факты

- PR #540 с документацией и скриптом воспроизводимости показал конфликт при фактическом вызове GitHub merge API, несмотря на предварительный статус `mergeable_state=clean`. Слияние не состоялось; конфликт нельзя обходить принудительным обновлением `main`.
- PR #550 закрыт без merge. Его изменения нельзя считать интегрированными только по факту закрытия; сравнение с текущей source-веткой показывает расходящуюся историю (5 коммитов только в source и 3 только в PR-ветке на момент сравнения).
- Последний Release ZIP по-прежнему относится к октябрю. Новый ZIP не публиковать до точной проверки source SHA, регрессий и человеческого подтверждения лицензий/прав на распространение.

## Ограничения этого снимка

Инвентаризация считает ветки и открытые PR, но не присваивает всем 627 веткам окончательный статус. Для этого требуется сравнение каждого head SHA с канонической линией и проверка содержимого/CI. Ветка не считается интегрированной, пока это не подтверждено diff/ancestry или конкретным merge commit.
