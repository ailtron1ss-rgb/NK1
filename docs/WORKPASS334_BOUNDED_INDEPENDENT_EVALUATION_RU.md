# WorkPass334 — общий временной бюджет независимой оценки

Дата: 2026-10-26  
Ветка: `fix/mega-cognitive-progress-tracking-2026-10-26-r3`  
Область: P23/Hermes independent candidate evaluation

## Что было не так

`serviceTimeoutMs` ограничивал отдельные вызовы candidate sandbox, independent verifier и safety scanner. Но оценка включает целый набор validation/holdout задач, поэтому допустимая длительность каждого отдельного вызова не давала верхней границы на весь эксперимент. При исчерпании общего времени важно не сохранить частичный результат как полноценный отчет и не продолжить запуск новых задач.

## Что изменено

- Добавлена настройка `evaluationTimeoutMs` для полного прохода по кандидату: default — **300000 ms (5 минут)**; допустимый диапазон — **10–1800000 ms (10 ms–30 минут)**.
- Для каждого сервисного вызова используется минимум из его локального timeout и оставшегося общего бюджета.
- Один общий deadline распространяется на весь список validation и holdout задач. Проверки budget выполняются перед запуском задачи, после ожидания каждого сервиса и перед формированием итогового digest.
- Истёкший общий budget приводит к `independent-candidate-evaluator-total-timeout`. В отличие от timeout отдельной задачи, он не превращается в диагностически неуспешный trial: весь прогон прекращается.
- Время измеряется через монотонные `performance.now()`, чтобы поправка системных часов не растягивала и не сокращала budget.
- Существующий per-service AbortSignal продолжает сигнализировать об отмене активной операции. Важно: внешний процесс действительно прекращается только если executor/host-owned service обрабатывает сигнал и завершает процесс; вызывающий код не может физически уничтожить произвольный Promise.

## Регрессии

В `tests/workpass227-bounded-independent-evaluation.mjs` добавлен сценарий, где первый executor не учитывает AbortSignal и разрешается позже общего budget. Ожидается, что evaluator отклонит весь прогон, сигнал вызова будет отмечен как aborted, и следующая задача не запустится. Есть также тест, блокирующий нулевой `evaluationTimeoutMs`. Сохранены прежние тесты локальных timeout-ов: executor и verifier fail closed на соответствующем trial, а timeout safety scanner отклоняет оценку.

Команда проверки: `npm run test:workpass227:bounded-independent-evaluation` из `runtime/neuro-kurisu`; затем полный WorkPass110 / P26 CI для typecheck и интеграционных регрессий.

## Границы доказательств

Изменение ограничивает длительность вычисления и поведение при timeout. Оно **не** доказывает эмпирический рост learning uplift, перенос навыков, автономность на длительном горизонте или готовность релиза. Для этого по-прежнему требуются независимые held-out задачи с парными seed-ами и реальная проверка deployment среды.
