# Проверка актуальности релизного ZIP NK1

## Два независимых статуса

Инспектор `tools/release_archive_inspector.py` разделяет:
- **целостность архива** — ZIP читается, CRC и размеры записей корректны, пути безопасны, нет запрещённых дубликатов, а при заданных значениях совпадают SHA-256 и размер GitHub Asset;
- **соответствие исходнику** — каждый файл архива сопоставлен с отслеживаемыми файлами выбранного Git worktree по пути и SHA-256.

`ok` / `archive.integrityOk` относятся только к физической целостности ZIP. Исторический архив может быть целым, но устаревшим.

`sourceMatchOk` означает, что нет изменённых файлов, файлов только в архиве и файлов только в исходнике. `releaseReady` — совокупный критерий: целостность ZIP плюс полное совпадение состава и содержимого с исходником. Это **не** подтверждение лицензий, работоспособности приложения, успешной сборки или готовности к публикации.

## Режимы

Обычный режим оставляет исторический аудит нестрогим: он сообщает расхождения, но не помечает старый ZIP как повреждённый и не завершает проверку ошибкой только из-за дрейфа исходника.

Для проверки кандидата на релиз включается строгий режим:

```bash
python3 tools/release_archive_inspector.py \
  --archive /path/to/candidate.zip \
  --source-root . \
  --archive-prefix auto \
  --require-source-match \
  --out artifacts/release-audit/candidate.json
```

Для опубликованного asset также следует передать `--expected-sha256`, `--expected-size` и `--release-tag`, взятые из метаданных GitHub. В строгом режиме ненулевой код возврата означает либо повреждение/несовпадение метаданных ZIP, либо расхождение с исходным деревом.

## Безопасность

Проверка читает ZIP без распаковки его содержимого. Она не меняет исходник, архив, GitHub Release, тег, лицензионные записи или baseline ZIP. Существующий workflow проверки опубликованных исторических ZIP остаётся нестрогим; новый строгий режим предназначен для кандидата на замену релиза.
