# Проверка соответствия ZIP исходному дереву NK1

## Что доказывает инспектор

Инспектор `tools/release_archive_inspector.py` разделяет две независимые проверки:

- **Целостность ZIP** — архив читается, CRC и размеры записей корректны, пути безопасны, нет запрещённых дубликатов, а при заданных значениях совпадают SHA-256 и размер GitHub Asset.
- **Соответствие исходному дереву** — каждый файл ZIP сопоставлен с отслеживаемыми файлами выбранного Git worktree по пути и SHA-256.

`ok` / `archive.integrityOk` относятся только к целостности ZIP. Исторический архив может быть целым, но отличаться от современного исходника.

`sourceMatchOk` означает полное равенство файлового состава и байтов между ZIP и отслеживаемым Git-деревом: без изменённых, source-only или archive-only файлов. `sourceMirrorOk` дополнительно требует валидную целостность ZIP.

## Важное ограничение для текущего NK1

Релизный пакет NK1 не является простым зеркалом Git-репозитория. Правила упаковки намеренно исключают часть репозиторных файлов и материализуют генерируемые публичные Live2D-ресурсы. Поэтому точное совпадение с каждым отслеживаемым Git-путём **не равно** готовности настоящего релизного пакета.

Для нынешнего релизного конвейера строгий режим ниже следует использовать только как консервативный аудит полного зеркала. Чтобы получить настоящий критерий release-ready, нужен отдельный утверждённый package-policy manifest: обязательные пути, допустимые generated assets, исключения, проверки восстановимости, SBOM/provenance и человеческое подтверждение лицензий. Не трактуйте `sourceMirrorOk` как лицензионное или продуктово-релизное одобрение.

## Режимы

Обычный режим оставляет исторический аудит нестрогим: он сообщает расхождения, но не помечает старый ZIP как повреждённый и не завершает проверку ошибкой только из-за source drift.

Для проверки полного зеркала включается строгий режим:

```bash
python3 tools/release_archive_inspector.py \
  --archive /path/to/archive.zip \
  --source-root . \
  --archive-prefix auto \
  --require-source-match \
  --out artifacts/release-audit/source-mirror.json
```

Для опубликованного asset также следует передать `--expected-sha256`, `--expected-size` и `--release-tag`, взятые из GitHub metadata. В строгом режиме ненулевой код возврата означает повреждение/несовпадение метаданных ZIP или отсутствие полного зеркального совпадения.

## Безопасность

Проверка читает ZIP без распаковки его содержимого. Она не меняет исходник, архив, GitHub Release, тег, лицензионные записи или baseline ZIP. Workflow проверки опубликованных исторических ZIP остаётся нестрогим и продолжает показывать расхождения как forensic evidence.
