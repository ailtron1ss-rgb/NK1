# WorkPass335 — причинная память намерения

Дата: 2026-10-24

## Цель

Сохранить для дальнейшей автобиографической консолидации не только действие/ответ, но и проверяемую причину выбора: что система собиралась сделать, какое намерение было выбрано, какие воспоминания были доступны, какое действие реально выполнилось, и чем исход отличается от прогноза.

## Единственный путь записи

Изменение проходит через уже имеющийся `OrganismRuntime → core.feedback → worldEvent`. Runtime не записывает напрямую в `MemoryOS2` и не вводит второе долговременное хранилище. Это сохраняет `MemoryOS2` владельцем памяти, а event/feedback flow — существующим каналом опыта и консолидации.

## Поля следа

`innerIntentMemoryTrace` версии 1 содержит:

- `intentId`, источник, мотив, причину, выбранную цель и состояние ресурсов;
- предложенное, выбранное, запланированное и фактически исполненное действие;
- ID памяти из активного контекста, использованного в этом цикле;
- ID существующих evidence receipts для наблюдения, прогноза, действия и исхода;
- доступность контрфактических ветвей и разрешён ли их бюджет;
- ожидаемую и наблюдённую награду, источник исхода, независимость, проверку, уверенность и ошибку прогноза;
- `attributionEligible`, выключаемый при смене действия гомеостатическим gate.

Идентификаторы указывают на существующие события/память, а не копируют содержимое этих записей. След ограничен активными 12 memory IDs и текущими receipts.

## Почему важно разделять прогноз и исход

Прогноз модели мира или shadow-simulator не является фактом о реальном внешнем мире. Поэтому след сохраняет источник результата и отдельно поля ожидаемой/наблюдённой награды, verification и independence. Результат симуляции не повышается до внешне подтверждённого только из-за наличия записи.

## Проверка и ограничения

Тест runtime-wiring проверяет, что след находится в реальном `core.feedback.worldEvent`, связан с memory IDs и evidence receipts и помечает несовместимое действие как непригодное для атрибуции.

Это подтверждает передачу provenance до существующего канала опыта. Это **не доказывает** само по себе успешное долговременное сохранение после перезапуска, качество retrieval или рост обучения. Для этого отдельно нужны restart/retrieval и matched holdout tests на одном и том же подтверждённом commit.


## WorkPass336 — ограниченная запись альтернативных будущих

В trace версии 1 добавлен sample до шести результатов существующего `CounterfactualEngine`. Для каждой ветви сохраняются ранг, максимум четыре первых действия, ожидаемая награда, неопределённость и короткое обоснование. Сохраняется также первое действие лучшей ветви и признак её расхождения с текущим планом.

Данный pass **не подменяет планировщик контрфактической ветвью**. Сценарии — прогнозы; реальный выбор остаётся у существующих систем планирования и action gate. После действия отдельно сохраняется grounded outcome, что позволяет сопоставлять предсказанное с фактическим без смешения этих категорий. Размер вклада ограничен, а долговременная запись проходит по текущему event/feedback пути.


## WorkPass339 — из event trace в действующий контур памяти

След намерения передаётся не только внутрь `worldEvent`, но и явным `causalMemoryContext` в тот же `OrganismCore.feedback`. Контекст содержит ID текущего trace, до 12 ID воспоминаний, реально доступных во время решения, и ограниченные evidence/verification сигналы. Core добавляет эти ID к штатному набору feedback-memory IDs и продолжает использовать единственный canonical MemoryOS2/memory-causal-economy путь.

Если внутренний гомеостатический механизм заменил действие, текущие memory IDs не получают decision-level причинного кредита за результат, поскольку итоговое действие не совпало с исходным предложением. Отдельная reconsolidation эмоций/неожиданности не отключается: она описывает реакцию памяти на пережитый исход, а не доказательство того, что воспоминание вызвало исполненное действие.

Тест runtime-wiring теперь проверяет обе стороны контракта — передачу ID из runtime и их применение Core feedback. Durable retrieval и эффект на отложенных задачах по-прежнему должны проверяться через конкретный restart/holdout эксперимент.
