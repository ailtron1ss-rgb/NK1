# WorkPass335 — причинная память намерения

Дата: 2026-10-24

## Цель

Сохранить для дальнейшей автобиографической консолидации не только действие/ответ, но и проверяемую причину выбора: что система собиралась сделать, какое намерение было выбрано, какие воспоминания были доступны, какое действие реально выполнилось, и чем исход отличается от прогноза.

## Единственный путь записи

Изменение проходит через уже имеющийся `OrganismRuntime → core.feedback → worldEvent`. Runtime не записывает напрямую в `MemoryOS2` и не вводит второе долговременное хранилище. Это сохраняет `MemoryOS2` владельцем памяти, а event/feedback flow — существующим каналом опыта и консолидации.

## Поля следа

`innerIntentMemoryTrace` версии 1 содержит:

- `intentId`, источник, мотив, причину, выбранную цель и состояние ресурсов;
- предложенное, выбранное, запланированное и фактически исполненное действие;
- ID памяти из активного контекста, использованного в этом цикле;
- ID существующих evidence receipts для наблюдения, прогноза, действия и исхода;
- доступность контрфактических ветвей и разрешён ли их бюджет;
- ожидаемую и наблюдённую награду, источник исхода, независимость, проверку, уверенность и ошибку прогноза;
- `attributionEligible`, выключаемый при смене действия гомеостатическим gate.

Идентификаторы указывают на существующие события/память, а не копируют содержимое этих записей. След ограничен активными 12 memory IDs и текущими receipts.

## Почему важно разделять прогноз и исход

Прогноз модели мира или shadow-simulator не является фактом о реальном внешнем мире. Поэтому след сохраняет источник результата и отдельно поля ожидаемой/наблюдённой награды, verification и independence. Результат симуляции не повышается до внешне подтверждённого только из-за наличия записи.

## Проверка и ограничения

Тест runtime-wiring проверяет, что след находится в реальном `core.feedback.worldEvent`, связан с memory IDs и evidence receipts и помечает несовместимое действие как непригодное для атрибуции.

Это подтверждает передачу provenance до существующего канала опыта. Это **не доказывает** само по себе успешное долговременное сохранение после перезапуска, качество retrieval или рост обучения. Для этого отдельно нужны restart/retrieval и matched holdout tests на одном и том же подтверждённом commit.


## WorkPass336 — ограниченная запись альтернативных будущих

В trace версии 1 добавлен sample до шести результатов существующего `CounterfactualEngine`. Для каждой ветви сохраняются ранг, максимум четыре первых действия, ожидаемая награда, неопределённость и короткое обоснование. Сохраняется также первое действие лучшей ветви и признак её расхождения с текущим планом.

Данный pass **не подменяет планировщик контрфактической ветвью**. Сценарии — прогнозы; реальный выбор остаётся у существующих систем планирования и action gate. После действия отдельно сохраняется grounded outcome, что позволяет сопоставлять предсказанное с фактическим без смешения этих категорий. Размер вклада ограничен, а долговременная запись проходит по текущему event/feedback пути.


## WorkPass339 — из event trace в действующий контур памяти

След намерения передаётся не только внутрь `worldEvent`, но и явным `causalMemoryContext` в тот же `OrganismCore.feedback`. Контекст содержит ID текущего trace, до 12 ID воспоминаний, реально доступных во время решения, и ограниченные evidence/verification сигналы. Core добавляет эти ID к штатному набору feedback-memory IDs и продолжает использовать единственный canonical MemoryOS2/memory-causal-economy путь.

Если внутренний гомеостатический механизм заменил действие, текущие memory IDs не получают decision-level причинного кредита за результат, поскольку итоговое действие не совпало с исходным предложением. Отдельная reconsolidation эмоций/неожиданности не отключается: она описывает реакцию памяти на пережитый исход, а не доказательство того, что воспоминание вызвало исполненное действие.

Тест runtime-wiring теперь проверяет обе стороны контракта — передачу ID из runtime и их применение Core feedback. Durable retrieval и эффект на отложенных задачах по-прежнему должны проверяться через конкретный restart/holdout эксперимент.


## WorkPass340 — единый источник learning provenance

Вызов `OrganismCore.feedback` теперь передаёт `LearningProvenance`, сформированный из финального решения `RealityLearningGate`. В нём сохранены классификация external/simulation, evidence/verification/independence/consequence, все масштабы обучения и уже ограниченные reward/success/surprise. Core больше не должен выводить другую политику обучения только по текстовой метке источника, если runtime уже вычислил и согласовал оценку доказательств.

Так объединены три части: реальные ID воспоминаний текущего цикла, eligibility атрибуции после гомеостатического перенаправления и фактические gate scales. Проверка компиляции и поведенческие регрессии должны пройти заново на точном новом SHA, прежде чем считать эту связку подтверждённой.


## WorkPass341 — корректировка единственного learning payload

Проверка компиляции обнаружила TS1117: WorkPass340 добавил второй ключ `learning` в объект `core.feedback`. Внимательная проверка показала, что этот же вызов **уже имел** канонический `LearningProvenance` ниже, с финальными значениями `RealityLearningGate`. Удалён дублирующий ключ и обновлена регрессия, которая теперь проверяет один исходный payload. Нового поведения в политике обучения за WorkPass340 не заявляется; причинная связка текущих memory IDs, добавленная WorkPass339, остаётся отдельным реальным изменением.


## WorkPass342 — защита эволюции личности от слабых исходов

Долговременное изменение path-dependence через связь воспоминания с личностью допускается только если текущий runtime передал авторитетный `LearningProvenance` и одновременно выполнены два условия: источник `external`, `verified01 >= 0.62`, `independent01 >= 0.62`. Без явного provenance сохраняется старое поведение ради совместимости старых вызовов Core, но основной `OrganismRuntime` уже передаёт эти данные.

Для B284 значение verification/independence теперь берётся из той же реальной provenance-записи. Симуляция не считается внешним подтверждением, а для вызовов с явной provenance отключается синтетическая `internalConsistency`-дорожка. Существующие внутренние механизмы B284 — повторное подтверждение, context holdout и cooldown — остаются конечными условиями продвижения идентичности.

Это не запрещает сохранять событие, обновлять обычную память или адаптировать прогнозирующий субстрат. Оно отделяет обучение по исходу от более редкого и долгосрочного изменения личности.


## WorkPass343 — единая семантика автономных входов

Фоновый cognitive clock уже вызывал `step(undefined, { deliberate: false, spontaneous: true })`, но публичный `autonomousStep()` не передавал `spontaneous`. Из-за этого `runAutonomousCycles()`, который делегирует в `autonomousStep()`, мог не активировать эндогенный режим внутреннего намерения.

Теперь `autonomousStep()` явно передаёт `spontaneous: true`, сохраняя прежнее управление `deliberate`. Все входы сходятся в тот же `OrganismRuntime.step → CanonicalCognitiveKernel` путь; отдельный автономный планировщик не создаётся.


## WorkPass344 — единое состояние эмоции для UI и Live2D

Текущая эмоция теперь берётся из последнего эпизода `EmotionAppraisalEngine`: label, valence, arousal, dominance, action tendency, cause и confidence. React UI и старый статический Live2D shell получают одну и ту же запись. Если эпизода ещё нет, сервер использует нормализованный fallback из cognitive field, не генерируя псевдоэмоции `thinking`/`focused`, которые не входят в контракт `EmotionLabel`.

Также исправлен контракт `GET /api/organism/avatar`: `public/avatar.html` ожидал корневые `awake`, `action`, `expression`, `body`, но endpoint возвращал только вложенное описание файлов `avatar`. Теперь endpoint оставляет инвентаризацию ресурсов и дополнительно отдаёт те сигналы, которые реально читает viewer. Выражение, наклон головы, взгляд, интенсивность, жест и голосовой акцент строятся из одной appraisal записи, текущего действия и реального speaking/listening состояния.

Поведенческий UI snapshot использует тот же helper, что снимает расхождение между внутренней эмоциональной оценкой и двумя потребителями аватара. Контрактные source assertions включены в WorkPass331 runtime-wiring test, а триггеры workflow расширены на server/avatar файлы.


## WorkPass345 — точное происхождение эмоциональной оценки

Петля обратной связи эмоций уже обновляла outcome calibration, но `external` выставлялся как `Boolean(outcome.evidenceSource)`. Из-за этого непустая метка симуляции могла быть ошибочно записана как `external-experience`. Теперь при наличии авторитетного `LearningProvenance` этот флаг вычисляется строго по `source === 'external'`; для старых вызовов без provenance сохранён совместимый fallback. Это не запрещает учиться по симуляциям: они остаются полезным внутренним опытом, но не маскируются под внешний мир.
