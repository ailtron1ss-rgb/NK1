# Карта пробелов до целевого состояния — WorkPass56 (2026-10-17)

Это инженерный backlog, не заявление о доказанном сознании и не оценка «человеческой эквивалентности». Функции считаются завершёнными только при связной реализации. Проверки — свидетельство, но не самостоятельный прогресс.

## WorkPass56 — дополнительная реализация, уже интегрированная в код

- `MemoryFabric.maintain()` запускает opt-in фоновую индексацию существующей памяти MemoryOS2 ограниченными пакетами. Запись канонических воспоминаний не зависит от embedding-provider.
- `MemoryOS2` принимает только корректные векторы неизменившихся активных записей; индекс ограничен, а ошибки получают content-bound exponential backoff.
- Когнитивное извлечение, фоновые пакеты и Memory Inspector используют одну сериализованную полосу запросов к провайдеру; при занятой модели когнитивный цикл не ждёт и возвращает canonical lexical/fuzzy результат.
- Memory Inspector показывает агрегированные показатели покрытия индекса, оставшихся элементов, retry и последней ошибки без текста воспоминаний.
- Перед cache/HTTP провайдером адаптер очищает распространённые credentials, bearer/API tokens, private-key blocks, emails, phone-like значения, credentialed URLs и длинные numeric IDs; сырые секретные значения не попадают в исходящий payload. Защита эвристическая, не universal PII classification.
- Использован источник Hexis MIT `services/memory_embeddings.py` как шаблон deferred/batched worker и повторов; SQL и второй memory-runtime не переносились.
- **Остаётся:** полная классовая PII-политика и UI выбора local/cloud, живой Ollama/llama.cpp запуск и измерение на целевом устройстве; широкое качество retrieval всё ещё `recallDelta=0`; Vite/browser/Live2D E2E, реальные provider/device receipts, фонемный lip-sync, clean-room rollback, полный nested-source license review и длительный soak.

## Закрыто или улучшено в WorkPass55

1. **Осиротевшие approval tickets после перезагрузки — DONE в безопасной модели.** Глобальный ActionApprovalCenter опрашивает канонический снимок ActionGateway, находит всё ещё ожидающие tickets без продолжения в текущей вкладке, показывает безопасное превью и позволяет явно отозвать. Исходное тело запроса не сохраняется, side effect никогда не запускается автоматически из старого ticket. Повторное выполнение требует нового явного действия пользователя.
2. **Двуязычный поиск воспоминаний с учётом концептов — PARTIAL.** MemoryOS2 получил доменные concept-группы для русско-английских перефразирований, балансированное расширение нескольких активных групп, intent для вопросов о любопытстве/личности, целях и причинах; alias-токены предварительно вычислены, чтобы не выделять строки для каждого кандидата. Контролируемые примеры проходят, но независимый holdout и общий прирост метрик пока отсутствуют.
3. **Баланс расширения концептов — DONE как инженерный механизм.** Алфавитное усечение заменено round-robin по самым релевантным активным группам. Исходные запросные токены не выкидываются; концептуальные синонимы остаются низковесными и не отменяют временные/эпистемические ограничения.
4. **Один владелец памяти и разрешений сохранён.** Retrieval остаётся в MemoryOS2/MemoryFabric, разрешения — в ActionGateway; новые независимые хранилища и конкурирующие runtime не добавлялись.

## Остаётся выполнить — функциональные и operational gates

Закрытие: чистая установка по lockfile, production build, реальный браузерный сценарий approve/decline/expiry/changed input/API error и Live2D на мобильном и desktop. До этого UI-код не считать подтверждённым в живом браузере.

8. **Обработка compound approvals.** Для каждой защищённой операции зафиксировать fingerprint parity, поведение второй approval после частичного side effect, idempotency key и reconciliation для неоднозначного результата. Не повторять side effect после потери ответа.

### P1 — память, тело и обучение

9. **Независимый benchmark retrieval.** Сформировать замороженный набор русско-английских запросов/перефразирований с hard negatives и несколькими релевантными воспоминаниями; сравнить текущий hybrid, BM25 и candidate bridge по Recall@k, MRR, false recalls и p95 latency. Текущий benchmark с 8 holdout запросами остаётся `recallDelta=0` и потолочным Recall@5; продвижение алгоритма запрещено до доказанного результата.
10. **Семантические embeddings в реальном окружении.** `LocalEmbeddingProvider` и `retrieveForCognition` существуют, но требуют установленной локальной модели/endpoint и измерения на целевом хосте; подтвердить качество, латентность, privacy boundary, бюджет VRAM/RAM и устойчивый lexical fallback.
11. **Аудио/виземы.** Заменить приближение по границам слов настоящей временной последовательностью аудио-envelope или фонем/визем от реального TTS; корректно обрабатывать interruption/cancel/reset. Не заявлять синхронизацию по фонемам без этого источника.
12. **Воплощённая связь тела и намерения.** Сопоставить позу, взгляд, жест, речь и состояние с одним общим body-action contract, получать подтверждение фактического motion и возвращать ошибку, если renderer не выполнил намерение.
13. **Самообучение после проверенных действий.** Продолжить обучение только от атрибутированных независимых внешних исходов, хранить причинные цепочки и исключать двойное credit assignment. Любое обновление сохраняет возможность отката.

### P2 — безопасность, происхождение и эксплуатация

14. **Чувствительность данных и облачная политика.** Общий фильтр остаётся эвристическим; требуется классовая политика контекста, UI-настройки local/cloud и доказуемая проверка сетевых payload.
15. **Самомодернизация.** Полный изолированный lifecycle `proposal → provenance/license → diff → tests/evaluation → explicit owner approval → promote → monitor → rollback`; активный код никогда не изменяется тихо.
16. **Чистое восстановление и rollback.** Fault-injected restore на чистом окружении с прерыванием во время commit, проверкой checksum, сохранением pre-restore snapshot и восстановлением без потери исходного состояния.
17. **Полный аудит лицензий 4 исходных архивов и вложенных источников.** Проверить для каждого реально переносимого компонента source URL/commit, license, notices, изменения и единственного runtime owner. Наличие исходника в архиве само по себе не означает интеграцию.
18. **Soak и target-host профиль.** Многочасовой idle/dialogue test, контроль роста памяти/очередей, restart, ограничение ресурсоёмких задач, локальные модели на целевом устройстве и измеренные degradation modes.

## WorkPass56 — новый результат по пробелу семантической индексации

19. **Отложенная индексация эмбеддингов — DONE в кодовой интеграции, PARTIAL в target runtime.** `MemoryFabric.maintain()` планирует низкоприоритетную пакетную индексацию только при `NK_EMBEDDINGS_RUNTIME_ENABLED=1`. `MemoryOS2` подбирает активные неподтверждённо-некварентинные записи, проверяет длину/конечность/норму вектора, сверяет content hash до сохранения, удерживает только ограниченный derived cache и повторяет сбои с capped exponential backoff. Эта операция не переписывает канонические memory facts и не блокирует запись воспоминаний.
20. **Один локальный embedding-provider lane — DONE в коде.** Background maintenance, live cognitive retrieval и Memory Inspector serially используют один embedding provider. Пока он занят, когнитивный цикл отдаёт canonical lexical/fuzzy результат; явный Inspector может подождать текущую работу вместо запуска конкурирующей нагрузки. Диагностика показывает только агрегаты, а не содержимое памяти.
21. **Источник интеграции:** адаптирован шаблон deferred batched worker/retry из сохранённого Hexis MIT `services/memory_embeddings.py`; его база данных и второй runtime не переносились.
22. **Условия закрытия семантического поиска остаются открытыми:** проверить реальную модель Ollama/llama.cpp на целевой машине, длительность и нагрузку; построить независимый labelled Russian/English holdout с hard negatives; доказать улучшение Recall@k/MRR/false recall/p95 latency. Нынешний широкий benchmark по-прежнему `recallDelta=0`, и функция не объявляется повышающей качество без этих данных.
