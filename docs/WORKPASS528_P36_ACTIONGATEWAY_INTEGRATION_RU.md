# WorkPass528 — реальное подключение саморазвития P36 к ActionGateway

**Дата:** 24 октября 2026 г.  
**Рабочая ветка:** `feature/learning`  
**Существующий PR:** [#79 → integration](https://github.com/ailtron1ss-rgb/NK1/pull/79)  
**Граница проверки:** исходники, тесты и workflow обновлены; текущие тесты и TypeScript typecheck не подтверждены запуском.

## Главный результат

Предыдущий этап закрыл доверие внутри самого P36, но в основном runtime до сих пор передавался лишь булев `verifiedNow`. Такой флаг не является независимым доказательством. Этот проход добавляет сквозной маршрут для оценщика: `ActionGateway` → `OrganismCore.finalizeToolOutcome` → P36.

### Reserved tool contract

Канонический ID оценщика: `organism.learning.p36.evaluate-evidence` (экспортируется из `P36AutonomousSelfDevelopment.ts` как `P36_EXTERNAL_EVIDENCE_TOOL_ID`).

При выполнении инструмента Core передаёт в P36:
- точную входную запись результата оценки;
- фактические `toolId`, `executionId` и `decisionId`, полученные от ActionGateway;
- исходный процесс-локальный verification receipt — только если действие успешно завершилось как `executed-verified` и внешний postcondition связан с реальной сохранённой записью выбранного решения.

P36 независимо повторно проверяет квитанцию через `isTrustedDecisionLinkedExternalPostcondition`: ID исполнения, ID решения, ID инструмента и полный нормализованный вход должны совпасть. Число, флаг `verified`, обычный tool ACK или квитанция без выбранного decision trace не разблокируют обучение.

Если данные неполные, результат не прошёл проверку или решение не связано с сохранённым trace, P36 учитывает попытку как неподтверждённую и не повышает веса. Отказы и успешные результаты записываются в журнал событий саморазвития. Ошибка read-only оценщика не переклассифицируется как неопределённый внешний side effect.

## Другие изменения этого прохода

- P36 state schema обновлена до версии 6.
- Миграция и runtime restore теперь используют один владеющий механизм `P36AutonomousSelfDevelopmentEngine.restore()`.
- Восстановление валидирует идентификаторы и домены гипотез, ограничивает сохранённые параметры, удаляет дубликаты и отзывает статус завершения/продвижения, если исходное доказательство нельзя повторно аутентифицировать. Счётчики проверенной зрелости, усвоенное мастерство и action bias не восстанавливаются лишь из сериализованных агрегатов.
- Регрессии P36 теперь используют проверку через ActionGateway и включают core-level сценарий для зарезервированного маршрута. P26 Learning Validation реагирует на изменения `OrganismCore.ts` и запускает P36 self-development, migration, integration, performance и autonomous-cycle тесты.

## Что подтверждено и что ещё требуется

**Подтверждено на уровне изменений кода:** зарезервированный маршрут добавлен в Core, требуемая квитанция привязана к ActionGateway execution/decision tuple, схема P36 v6 синхронизирована с миграцией, тестовые сценарии и workflow подключены.

**Пока не подтверждено запуском:** TypeScript typecheck, новые тесты и точный HEAD CI. Во время прохода GitHub API не вернул проверяемый запуск workflow для текущего HEAD, а локально выполнить suite из-за недоступности GitHub из контейнера не удалось. Поэтому нигде не заявляется, что тесты прошли.

**Открытый интеграционный пункт:** производственная сборка должна зарегистрировать настоящий host-owned independent evaluator под зарезервированным ID. Он должен получать фактические baseline/treatment/holdout-данные и выдавать верифицируемый external postcondition, а не повторять утверждение самого P36. Тестовый evaluator в регрессии — только fixture; он не установлен в production. После его регистрации нужны exact-HEAD CI, замеры holdout/retention/transfer и подтверждённый результат после перезапуска.

Никакого эмпирического прироста способности к обучению по числу коммитов не заявляется. `main` и GitHub Release ZIP не менялись.
