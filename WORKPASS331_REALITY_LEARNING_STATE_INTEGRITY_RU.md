# NK1 WorkPass331 — целостность сохранённого состояния обучения на реальных данных

**Дата:** 2026-10-26  
**Рабочая ветка:** `workpass331-reality-learning-state-integrity`  
**Область:** `runtime/neuro-kurisu/src/organism/system/RealityLearningGate.ts`  
**Статус:** изменения закоммичены; runtime-проверка ещё не выполнена.

## Обнаруженная проблема

`RealityLearningGate.restore()` ранее накладывал содержимое сохранённого объекта на дефолтное состояние с помощью широкого spread. Это означало, что значения счётчиков, агрегаты и история решений не проходили нормализацию. При повреждённом или устаревшем снимке состояние могло содержать отрицательные/небезопасные счётчики, NaN/Infinity в агрегатах или записи с невалидным источником.

Вторая проблема — история решений хранится в порядке «самое новое сначала», но восстановление брало `history.slice(-256)`. Для истории длиннее лимита это сохраняло старый хвост и отбрасывало свежие решения, ухудшая диагностическую и learning-континуальность.

## Что изменено

1. **Восстановление по allowlist.** `restore()` больше не копирует произвольные поля снимка. Оно пересобирает объект состояния из известных полей и дефолтов.
2. **Счётчики.** Отрицательные, дробные, небезопасные или нечисловые значения заменяются безопасными дефолтами. Общий счётчик не может быть меньше суммы external/simulation decisions; счётчики attenuated/strong не превышают общего количества решений.
3. **Агрегаты.** Mean-значения проверяются на конечность и ограничиваются диапазоном `[0, 1]`; повреждённые числа заменяются соответствующими дефолтами.
4. **История.** Невалидные решения и неизвестные source отбрасываются. Свежайшие 256 записей сохраняются через `slice(0, 256)`. Если `last` повреждён, последняя запись берётся из первого валидного элемента истории.
5. **Регрессии.** `tests/p2840-reality-learning-gate.mjs` теперь проверяет NaN/Infinity, out-of-range агрегаты, плохие счётчики, битую last/history, работу после restore и усечение истории из 300 элементов с сохранением самых свежих 256.
