# WorkPass65 — экспериментальный план

## Цель

Проверить, повышает ли подключение P29/P30 к выбору действий качество решения, а не только меняет численную оценку кандидатов.

## Экспериментальные группы

1. Baseline — новый вклад выключен.
2. Governance-only — только P29.
3. Transfer-only — только P30 transfer priors.
4. Full integration — P29 + P30.

## Зафиксировать до запуска

- Общие task streams и paired seeds для всех групп.
- Независимый holdout, который не используется для настройки коэффициентов.
- Метрики: task success, regret, calibration error, forgetting, catastrophic failures, latency, peak RAM и ресурсная стоимость, если доступно.
- Минимально значимый эффект и допустимые регрессии.
- Версии кода, конфигурации, seed, окружение и сырые результаты каждого прогона.

## Правила решения

- Не менять пороги после просмотра holdout.
- Считать разницу между группами попарно и показывать интервалы неопределённости, а не только среднее.
- Не продвигать вариант, если улучшение неустойчиво между seeds или цена по памяти/задержке неприемлема.
- Retrieval остаётся not-promoted, пока recallDelta не станет положительным на размеченном независимом наборе.
- Сохранять неудачные результаты; не удалять seeds и не выбирать только удачные запуски.

## Незакрытые release gates

- Полный verify:deep.
- Production UI build и настоящий browser/Live2D E2E.
- Независимый multi-seed holdout.
- Длительный endurance soak.
- Проверка лицензий встроенных/заимствованных компонентов.

## Доставка

ZIP размером около 129 MiB не следует хранить как обычный Git blob. Предпочтительны GitHub Release assets или Git LFS. Скрипт publish-workpass64.ps1 создаёт Release и прикладывает проверенные архивы с локального компьютера после авторизации GitHub CLI.
