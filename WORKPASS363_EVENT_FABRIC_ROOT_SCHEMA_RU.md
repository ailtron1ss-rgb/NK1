# NK1 WorkPass363 — атомарная проверка корневой схемы CognitiveEventFabric

**Дата:** 2026-10-26

**База:** workpass362-event-fabric-restore-boundary на 2443a83c3218952a5da3d9c29dcd68ac2b267470  
**Статус:** изменения опубликованы; exact-head CI ожидает результат. PASS не заявляется.

## Найденный дефект

restore() отличал старую схему только сравнением значения version с undefined. Поэтому явное version: undefined выглядело как отсутствие версии. Аналогично, присутствующие неправильные типы recent, receiptEvents, receiptProjectionIndex молча трактовались как пустые коллекции, а неправильный total сбрасывался к числу восстановленных узлов. Это позволяло испорченному корневому snapshot без исключения заменить живой журнал пустым или неполным состоянием.

## Изменения

- Добавлена проверка наличия поля через собственный property descriptor, отделяющая отсутствие поля от присутствующего undefined.
- Если поле версии присутствует, принимается исключительно schema v1.
- Присутствующие поля коллекций должны быть массивами; неправильно типизированные корневые поля отклоняются до декодирования и до любых изменений живого состояния.
- Присутствующий total обязан быть неотрицательным safe integer. Legacy snapshot по-прежнему может вообще не содержать эти необязательные поля.
- Регрессии проверяют строковый/undefined/unsafe total, неправильные типы трёх коллекций, version: undefined и эквивалентный снимок живого журнала после каждого отказа.
